## §1 范围与八态定义

**范围**：本次盘点实机逐一点开的 19 个养成/成长相关入口（角色属性战力、装备、称号、戒指、时装、魂骨、技能、修炼、翅膀、神器、坐骑、伙伴、伙伴洗髓、伙伴阵型、锻造、神格、我要变强、提升、更多菜单）。不含 C2 总表中纯运营活动/公会/副本等非养成条目。

**八状态定义（与 C2 总表口径一致）**：

| 状态 | 含义 |
|---|---|
| VERIFIED_WORKING | 已实机运行验证可用（打开正常、数据真实渲染、可关闭） |
| IMPLEMENTED_UNVERIFIED | 代码/UI 已实现、已实机打开但数据未闭环或未完整验证 |
| EXISTS_BROKEN | 面板存在但运行有问题（空数据/空白/渲染异常） |
| PARTIAL | 仅部分功能完成（占位文本/条目未接数据） |
| RESOURCE_ONLY | 仅确认资源存在 |
| NEEDS_IMPLEMENTATION | 有充分证据需实现/修复 |
| BLOCKED | 依赖或前置系统阻塞（当前角色/结婚/数据不具备验证条件） |
| UNKNOWN | 证据不足 |

**本清单状态来源优先级**：实机盘点（c2_2_runtime_survey）> C2 总表实测回填 > C0 静态分类。冲突见 §4。

## §3 试点候选组分析（按用户建议顺序核验）

> 用户建议的试点顺序为：① 角色属性/战力/装备 → ② 技能 → ③ 伙伴 → ④ 翅膀/魂骨/时装 → ⑤ 增幅/神器/命格/阵法。逐组核验结论如下。

### 第一组：角色属性/战力/装备 —— ✅ 采纳为首试点（聚焦 F1 修复闭环）
- **实机状态**：VERIFIED_WORKING（含 F1 首帧时序缺陷）。
- **结论**：作为第一个试点，但试点范围应收敛为「F1 首帧时序修复闭环」，而非重开面板做功能。
- **理由**：
  1. 闭环最短——缺陷已定位为「面板 onEnter 渲染早于 10304/装备属性到达」，重开自愈、HUD 全程正确，非持久损坏；
  2. 修复路径明确——服务端在 10300 RoleInit 后主动 push 10304 战力（+ 装备属性），或客户端在面板 onEnter 时主动请求；
  3. **战略杠杆最高**——战力是所有养成系统的统一出口（power/service AttrPower 31 属性），先把角色总战力基准打通，等于为后续翅膀/神器/坐骑/命格等所有养成系统提供统一战力校验基准；
  4. 风险低、可在现有已 VERIFIED 面板上做最小改动回归。

### 第二组：技能 —— ⚠️ 次优先，但根因在服务端，不能与第一组混为「UI 试点」
- **实机状态**：EXISTS_BROKEN（左列表空白、3 槽未激活）。
- **结论**：排在第一组之后，定位为「服务端技能列表 push 补齐」任务，而非界面修复。
- **理由**：根因是服务端未推技能列表（10401 hero_bag / 10621 skill_list），UI 框架本身可用（修炼子 tab 已 VERIFIED_WORKING 即证明面板壳子正常）；需服务端补业务数据，闭环长度大于第一组 F1；技能详情/升级因列表空无法点选验证。

### 第三组：伙伴 —— ✅ 采纳为第三组（需先备测试数据）
- **实机状态**：伙伴主面板+阵型 VERIFIED_WORKING；洗髓 IMPLEMENTED_UNVERIFIED。
- **结论**：可作为第三组，但前置条件是先造一个「已拥有伙伴」的测试账号。
- **理由**：当前角色伙伴列表为全图鉴态、无任何已拥有伙伴，洗髓/培养闭环无法验证（BLOCKED 于测试数据）；阵型/图鉴已 VERIFIED；洗髓消耗真值是 HANDOFF 缺口#2，需随测试账号一起取证。建议与第一组并行准备测试数据，不阻塞 F1 修复。

### 第四组：翅膀/魂骨/时装 —— ⚠️ 拆成两档，不可整组并列
- **实机状态**：翅膀 VERIFIED_WORKING、时装 VERIFIED_WORKING、魂骨 IMPLEMENTED_UNVERIFIED。
- **结论**：翅膀/时装可直接进回归（协议字段齐全、服务端已实现）；魂骨应划入服务端开发，不属 UI 恢复试点。
- **理由**：翅膀 CS_11600 / 时装 CS_10573 族字段均 CONFIRMED、服务端 VERIFIED，实机数据真实，可批量回归；魂骨 SYS_GROWTH_006 服务端 soulbone/ 目录存在未接线、无协议、槽位空+等级锁，是纯服务端缺口，放在 UI 试点里无法闭环。

### 第五组：增幅/神器/命格/阵法 —— ⏸ 后置
- **实机状态**：神器 VERIFIED_WORKING、命格/阵法服务端已实现（19400 族 / 11237 VERIFIED），增幅 SYS_GROWTH_007 未接线、神格 godredeem client-only。
- **结论**：后置到第一组 F1 闭环 + 统一战力基准建立之后再批量回归。
- **理由**：神器/命格/阵法协议与服务端已就绪，可回归但非高频路径（多藏在进阶子菜单/隐藏入口）；增幅（server/amplification 未接线）与神格（godredeem 无 handler）属未实现系统，需服务端开发；在统一战力基准未打通前，这批养成分项战力即使渲染也无法与总战力 724112 对账。

**试点顺序总结论**：① F1 战力/装备首帧修复（最短闭环+统一基准）→ ② 技能服务端列表 push → ③ 伙伴（先备拥有伙伴的测试号）→ ④ 翅膀/时装回归（魂骨转服务端）→ ⑤ 神器/命格/阵法批量回归（增幅/神格转服务端开发）。
