## §1 范围与八态定义

### 1.1 本分片覆盖范围

C2.3 聚焦「玩法与内容界面」——即**角色养成（C2.2 已测）之外**的主循环界面：任务/世界探索、NPC 交互、野外战斗、队伍/地图、挂机/副本、商城/货币/礼包/VIP、好友/邮件/宗门/排行/签到/在线福利/日常/活动顶栏。
C2.1 已闭环（登录/主 HUD/角色背包/设置/CommonAlert）与 C2.2 已闭环（养成 24 行）的界面不在本表重复实测，仅在「C2 总表行引用」列挂接其 ui_id。

### 1.2 八态定义（与 C2 总表一致）

| 状态 | 含义 |
|---|---|
| VERIFIED_WORKING | 已实机运行验证可用（面板打开 + 数据正确 + 交互闭环） |
| IMPLEMENTED_UNVERIFIED | 服务端/客户端代码已实现，未实机打开验证 |
| EXISTS_BROKEN | 面板存在但交互有问题（点击无响应/数据错位/渲染缺陷） |
| PARTIAL | 仅部分功能完成（框架在但内容空/子功能断链） |
| RESOURCE_ONLY | 仅确认资源/配置存在，无运行态 |
| NEEDS_IMPLEMENTATION | 有充分证据需实现/修复 |
| BLOCKED | 依赖或环境阻塞（入口不可达/相机位置限制） |
| UNKNOWN | 证据不足，无法判定 |

### 1.3 数据来源五分类（本清单专用列）

- **真实 CS**：盘点 tcp.log 抓到该面板产生真实客户端→服务端请求帧（非纯本地渲染）。
- **本地 UI**：面板打开/切换/展开走客户端本地逻辑，无对应 CS 请求。
- **真实 CS + 本地渲染混合**：列表数据来自服务端，rail/tab 切换本地。
- **空数据**：面板框架打开成功，但列表/内容区为空（单人 mock 或服务端未推）。
- **占位**：UI 渲染但后端未接线（按钮无响应/不产生 CS）。

> **本次盘点核心结论（survey §5）**：与 C2.2「养成面板走本地缓存」不同，**玩法面板（任务/商城/邮件/宗门/排行/签到）均产生真实 CS 网络往返，非纯本地缓存**。

## §3 试点候选组分析（用户建议顺序核验）

> 用户建议恢复顺序：**① 修复补齐任务/NPC/寻路/场景切换 → ② 战斗/结算 → ③ 副本 → ④ 挂机 → ⑤ 商城/货币/礼包 → ⑥ 活动/邮件/排行/社交**。
> 逐组结合本次实机八态给出结论与理由。

### 组① 任务 / NPC / 寻路 / 场景切换 —— ✅ 建议优先，主体已通，仅补 3 个断链

- **结论**：这是性价比最高的一组，**主体 VERIFIED_WORKING，只剩 3 个明确断链**。
