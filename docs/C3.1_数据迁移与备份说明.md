## §2 迁移机制现状

### 2.1 已有机制

| 机制 | 现状 | 证据 |
|---|---|---|
| **SQLite 直操作** | ✅ 唯一方式。所有读写走 `persistence/db.py` 的 sqlite3.connect + 原生 SQL | A §1.3 |
| **CREATE TABLE IF NOT EXISTS** | ✅ 重启时不破坏旧表，缺失表自动建 | persistence/db.py:60-109；A §2 P10 |
| **ALTER TABLE 幂等补列（部分）** | ✅ race_state（mock_server.py:9036）/ guaji_state（:9334）有 `ALTER TABLE ... ADD COLUMN` 幂等 | A §2 P11 |
| **手动 DB 快照** | ✅ roles.db.bak_before_bagclean / pre_bagfix | server/state/ |
| **代码滚动备份** | ✅ 141 个 .bak 文件 | server/ |

### 2.2 缺失机制（如实记录）

| 缺失项 | 现状 | 影响 |
|---|---|---|
| **无统一 migration 框架** | 部分表有 ALTER 幂等、部分没有；注释明确警告"CREATE TABLE IF NOT EXISTS 不给旧表加列 ⇒ 旧库会静默缺列"（mock_server.py:2442） | 旧库升级后新增列缺失，运行时 INSERT/UPDATE 报"no column"或静默 NULL |
| **无事务包装** | A 分片未核验货币 / 任务 / 发奖是否在同一事务内提交（UNKNOWN） | 写库中断时可能半提交 |
| **无自动化回滚脚本** | 需手动 copy .bak 回 roles.db | 恢复时依赖人工操作 |
| **无按时间滚动的 DB 备份** | 仅 2 个手动快照（before_bagclean / pre_bagfix） | 误操作后只能回到这两个时间点 |
| **无 schema 版本号** | 无 user_version PRAGMA 或 migration 表 | 无法判断当前库处于哪个 schema 版本 |

## §3 风险与最小建议

### 3.1 风险清单

| # | 风险 | 等级 | 证据 |
|---|---|---|---|
| R1 | **旧库升级静默缺列**（A §2 P11）：role_market_goods（:2452）/ role_point（:2870）等多处 CREATE TABLE IF NOT EXISTS 后紧跟 ALTER，但 ALTER 未做幂等保护 | 中 | mock_server.py:2442 注释 |
| R2 | **diamond/gold 双路漂移**（A §2 P1/P2）：roles 列 stale，若未来 role_state() 合并顺序翻转会立即丢资产 | 高 | roles.gold=1800140 vs role_assets.gold=1800041；roles.diamond=0 vs role_assets.diamond=100000 |
| R3 | **20+ admin 命令直写 DB 无审计**（A §2 P7）：reset 命令（L1620-1632）直 DELETE 多张表无 gm.log | 中 | gm.log 仅 8 行 |
| R4 | **无自动化回滚**：误操作后只能手动 copy .bak | 低 | A §3.4 |
| R5 | **备份链无清理策略**：141 个代码 .bak + 999 个 tcp_*.bin 持续堆积 | 低 | 实机扫描 |

### 3.2 最小建议（只列不实施）

1. **建立统一 migration 框架**：在 `persistence/db.py` 加 `_ensure_columns(con, table, {col: default})` 幂等函数；所有新增列的表在 db_init() 里集中跑一遍；加 `PRAGMA user_version` 记录 schema 版本；
2. **DB 备份自动化**：restart_server.ps1 启动前自动 copy roles.db → roles.db.bak_YYYYMMDD_HHMMSS；保留最近 N 份；
3. **统一货币权威**：废弃 roles.gold/diamond/coin 列（或所有写点双写同步），消除 R2；
4. **admin 命令统一审计**：do_GET 入口包一层 log_gm()，覆盖 reset 等高风险操作；
5. **备份清理脚本**：定期清理 tcp_*.bin（保留最近 N 天）与旧 .bak（保留最近 N 个 revision）；
6. **事务包装**：货币扣减 + 发奖在同一事务（BEGIN IMMEDIATE ... COMMIT），防止半提交。
