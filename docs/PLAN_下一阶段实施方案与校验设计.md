> # ★★★ R193：**解构器工程的决定性突破 —— 实现 `IST`/`JMP`**
>
> ★★★ **`config_item` 从 120 字符 → 659004 字符（×5492 倍）**，**3013 条物品数据全部解出**。
>
> **根因链**（三步诊断，每步有证据）：
> 1. 解构只出 `{Config:{ItemDecomList:{18071:{...}}}}`（1117 物品全丢）
> 2. 跟踪寄存器：`TNEW a=1` 出现 3 次；`GSET Config=R1` 出现 2 次
> 3. ★ 看末尾 30 条 ⇒ **真相**：
>    ```
>    #65438  TSETS   R0['ItemData'] = R1      ← ★★ 物品表已挂到 Config['ItemData']
>    #65453  GGET    a=1                      ; R1 = Config
>    #65454  IST     a=0                      ; if R1 then
>    #65455  JMP     a=2                      ;   goto pc+1+(d-0x8000)
>    #65456  TNEW    a=1                      ; R1 = {}   ← 只在"Config 为空"时
>    #65457  GSET    a=1                      ; Config = R1
>    ```
>    ⇒ **Lua 的 `if not Config then Config = {} end` 惯用法**！
>    ★ 而 **`deconstruct` 不处理 `IST`/`JMP`** ⇒ **照直执行 `TNEW`+`GSET`**
>    ⇒ **`Config` 被换成空表** ⇒ **`ItemData` 全丢**。
>
> **修**：**实现 `IST`/`JMP`**（`JMP` 目标 = `pc + 1 + (d - 0x8000)`；`IST` 为真才跳）
> ⇒ **救回 5 个**（`config_item` **659004**、`config_common` 1365、`config_mon_data` 311、
> `config_skill` 737、`config_skill_magic` 743）。
>
> **★ 纪律第 35 条**：**"解构/反编译"类工具的"控制流指令"必须实现** ——
> `IST`/`JMP` 看起来"只影响控制流"，但**配置脚本大量用 `if not X then X = {} end` 惯用法**
> ⇒ **不实现跳转 ⇒ "无条件执行初始化" ⇒ 把已挂好的数据覆盖成空表**。
> ★★★ **判据**：**"解构结果异常小" ⇒ 先查"未处理的控制流指令"**。

| 4 | **裁图 + 视觉读数** | 只用于"面板里出现了什么文字"，**不作为数值正确的唯一证据** |
