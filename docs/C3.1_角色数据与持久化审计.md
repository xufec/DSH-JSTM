- **权限**：HTTP `/DSH_ADMIN/*` 无任何 token/IP 白名单校验（L786 直接进入路由）；绑机私服可接受。

## §4 结论

### 4.1 权威来源初步判定

- **身份类字段**（rid/uid/name/level/career/sex/scene_id/x/y/dir/vip_level/title/status）→ `roles` 表（权威）
- **货币/资产类**（gold/coin/coupon/diamond/exp/vitality/sinew/practice_exp/...）→ `role_assets` 表（权威，role_state() 合并时覆盖 roles 同名列）
- **战斗属性类**（strength/intellect/armor/.../hp_max/...）→ `role_attr` 表（权威）
- **任务进度** → `missions` 表（权威）
- **背包/装备/仓库** → `bag_items` / `equip_items` / `store_items`（权威）
- **技能列表** → 当前仍为 config.json 静态（`cfg['skills']`），**未 DB 化**（KNOWN_GAP）
- **伙伴/外观/养成线** → 各独立 role_* 表（role_heros/role_fabao/role_wing/role_mingge/...）

### 4.2 风险最高的 3 项

1. **【P1+P2 合并】diamond/gold 双路存储且已漂移**（最高风险）
   - 证据：roles.gold=1800140 vs role_assets.gold=1800041（差 99）；roles.diamond=0 vs role_assets.diamond=100000
   - 影响：DB 巡检/旁路 SQL 会读到过期值；若未来 role_state() 合并顺序翻转会立即丢资产；当前客户端 UI 正确是因为 role_assets 覆盖 roles
   - 建议：明确"资产类一律走 role_assets，roles 表废弃 gold/diamond/coin 列"或"所有写点双写同步"（仿 add_role_exp L6182）

2. **【P7】20+ 条 admin 命令直写 DB 无 gm.log 审计**
   - 证据：gm.log 仅 8 行（3 种 action），而 do_GET 路由里 20+ 条命令写库无审计
   - 影响：事后无法追溯"谁发了什么道具/改了什么进度"；reset 命令 DELETE 多张表无审计
   - 建议：do_GET 入口包统一审计中间件，所有写库 action 一律 log_gm()

3. **【P8】发奖幂等不统一**
   - 证据：12403 任务提交有幂等；shop_try_buy 走 reward.grant；但 mission_progress_advance、mail 附件、addbag 未走 grant
   - 影响：客户端重发请求时重复发经验/道具；GM addbag 无幂等可反复刷
   - 建议：所有发奖点统一走 reward.grant(reference_id=...)
