### 1.3 setassets 校验（①）
- **输入**：`curl /DSH_ADMIN/setassets?rid=1001&gold=-100`；再 `mode=add gold=100`；再 `mode=set gold=1800041`。
- **预期**：负数→HTTP 400 拒绝且 DB 不变；正常 +100 允许；随后还原基线。
- **实际**：
  - 负数 → **HTTP 400** `{"ok":false,"error":"gold must be >= 0 (got -100)"}`，DB gold 未变（1800041）。
  - `mode=add gold=100` 允许（→1800141）；`mode=set gold=1800041` 还原。
- **结果**：✅ PASS
- **证据**：curl 返回报文；DB 快照前后一致。

### 1.4 审计不干扰正常流程（①）
- **输入**：执行两次 setassets 写（add +100、set −100）+ 一次游戏内商城购买。
- **预期**：gm.log 正常记录、无重复/错记；正常业务不被审计干扰。
- **实际**：gm.log 两次写各记一行（23:50:10 add +100、set −100），无重复；被 400 拒绝的负数未落审计（门控在 set_assets 前）；游戏内商城购买不写 gm.log（设计如此，gm.log 只追踪 /DSH_ADMIN 管理命令）。
- **结果**：✅ PASS
- **证据**：`server/logs/gm.log`。

### 1.5 击杀幂等（③）
- **输入**：重复提交同一次击杀（reward reference_id=`kill:20001:1001`）。
- **预期**：奖励入账一次；重复提交奖励不重复、进度不叠加。
- **实际（确定性机制验证）**：
  - reward_log 已有 `kill:20001:1001`（source=battle）一行。
  - 再次 `grant(1001,[{asset:gold,9999}],'kill:20001:1001')` → 返回 `{ok:True, already:True, applied:[]}`。
  - gold 1799942 不变 / exp 14439 不变 / reward_log 行数 10 不变。
  - 代码门控 mock_server.py L9940：`if not _kill_gr.get('already'):` 才 `mission_progress_advance`——重复结算进度不叠加。
  - 任务 10020（target=20001）value=1（仅推进一次）。
- **结果**：✅ PASS（幂等机制确定性证明）
- **NOT_RUN 项**：野外交互战斗"杀一只怪→结算→重复提交"的完整 tcp.log+DB 双证据未能在本会话实机触发——角色在城内 scene=10001，点霍雨浩仅出对话气泡（cmd=10204 移动），点"挂机→自动巡逻"未发 154xx 流量、未传送野外。幂等机制本身已由 reward_log PK + L9940 门控确定性证明。
- **证据**：q_idem.py 输出；reward/service.py L51-78；mock_server.py L9928/L9940。

## 二、回归与基线（任务 2）

### 2.1 miniloop
- **命令**：`python server/minloop/selftest.py`
- **结果**：检查项 **144，通过 135，失败 9**。
- **失败清单（全部聚集在礼包/10500/10505/10303 子系统）**：
  1. 使用真实礼包 100 ⇒ 10505 code=1
  2. 开礼包 ⇒ 恰好一次 10500 进包推送（帧数=0）
  3. 10500 推送物品 bid 逐条等于礼包内容（pushed=[] vs real 21200-21205）
  4. 背包多出礼包内容（before=0 after=87 期望+115）

  6. 含货币码礼包 21900 ⇒ exp 增加（1000→1000 未增量）
  7. 货币码不进背包（bag 105→109）
