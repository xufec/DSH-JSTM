## 2. 服务端缺陷：根因与修复

### D1 · 移动校验恒用「史莱克城」的 MapBlock

**现象**（实机 `tcp.log` 实录）：

```
!! [move] cmd=10204 rid=1001 scene=10001 目标不可走 (10,58) → 回复权威坐标 (44, 68)
.. [move] 已改用服务端权威坐标 (44,68)
** DB persist role 1001 pos=(44,68)
```

(10,58) 正是**目标图 10005（乾坤日月谷）的默认出生点**——它在 10005 里完全合法，却被按 10001 的可走性判死。

**根因**：`_current_bid(handler)` 只读 `handler.cfg['spawn']['bid']`，**恒为 10001**，与玩家实际所在场景无关。
⇒ 任何切图（GM 传送 / 挂机图 / 副本）之后，移动校验都拿错地图 ⇒ 误拒 + 回退坐标 + 把错值落库。

**修复**：`_current_bid()` 改为**优先取每连接实际进图记录** `handler._last_enter[0]`（由 `_send_10200` 写入，
语义就是"服务端刚把玩家放进哪个图"），无记录才回退 spawn 配置。

### D2 · 登录恒进 10001 ⇒ 私服只有一张图可玩

**根因**：10102 登录分支写死 `self._send_10200(self.cfg['spawn']['bid'])`（=10001）。
⇒ GM 传送、`config_guaji` 的 8 个挂机图（10002–10011）、副本所在地**一重登即丢**。

**修复**：新增 `login_scene_bid(cfg)`——优先读存档场景 `roles.scene_id`，并校验它在 `config_map` 里
（`map_def_xy` 返回非 (0,0)）；否则回退 `spawn.bid`，保证不会把玩家丢进不存在的图。

### D3 · 10300 补推 10200 又把人拽回旧图

**根因**：`repush_10200_on_init` 分支同样用 `spawn.bid`。客户端每次场景初始化完毕发 10300，
服务端就再推一次 10200(10001) ⇒ **当场撤销**刚完成的切图。

**修复**：改用 `_current_bid(self)`（复用 D1 的修复），推"当前实际所在图"。

### D4 · 10933 / 10934 分发遮蔽（死条目）

**现象**：项目自带门禁 `tools/lint_dispatch_shadow.py` 报：

```
★ 同一命令存在多个专用分支（2 条）—— 后者永远不会执行：10933 出现 2 次 / 10934 出现 2 次
```

**根因**：C3.3-D 已在**较早位置**为离线挂机开关装了专用实现（`if cmd == 10933/10934` 并 `return`），
但更靠后的「109xx 看他人详情族」元组里**仍留着 10933/10934**。这两条永远收不到，是死条目；
它本身不改行为，但正是历史上把 `15403` 遮蔽掉的那类隐患（同一命令号归属不明）。

**修复**：从该元组删除 `10933`/`10934`，让每个命令号归属唯一。
`_dedicated_cmds()`（默认响应兜底用的专用号集合）成员不变 ⇒ **零行为变更**。

### D5 · 下发给客户端的配置是探针，URL 全局全丢

**现象**：`server/url_config_ewan.lua`（`/update/config/url_config_ewan.lua` 的下发内容）**只剩**
`DSH_PROBE` 上报代码，`URL_PATH_ALL` / `URL_PATH` / `CDN_URL` / `get_servers_url` / `get_notice_url` /
`UPDATE_VERSION_MAX` **全部丢失**——是某轮诊断留下的探针版覆盖了生产版。

**为什么之前没暴露**：老装机器 `<writable>/assets/src/url_config.lua` 已有缓存，客户端不回取，
且 `get_servers_url` 被注入 APK 的 `server/dsh_fake_login.lua` 兜底了。
但**全新安装 / 清数据后**客户端会拉到空壳配置 ⇒ 抛
`attempt to call global 'get_servers_url' (a string value)` 并中断登录界面构建。

**修复**：恢复生产版（探针版另存 `url_config_ewan.probe_only_20261016.lua`），并加注释说明为何不能再用探针覆盖。
验证：`lua-check` **OK**；HTTP 实测下发内容含全部 6 个全局，HOST/PORT 替换正常；
重启客户端后照常进游戏（见 §5）。

### D6 · miniloop 门禁 flaky（测试侧）

**现象**：同一份代码在同一机器上跑出 **145/145、143/145、140/145、139/145** 不等，
失败项全部集中在礼包 `10505 → 10500` 开箱路径。

**根因**：`recv_all()` 的口径是"收到过数据后一出现 idle 空档就返回"，而开 229 件礼包的用例
只给了 `wait=0.8 / idle=0.15`。机器有负载时帧间空档超 0.15s ⇒ 10505 到了、10500 还没到就返回，
后续 4~5 条断言连锁误报。

**举证与修复**：先用**改动前备份**复现（143/145，同样 2 项失败）证明非本批引入；
再把该重活路径的 4 处调用改为 `recv_all(3.0, 0.6)` / `recv_all(2.0, 0.5)`。
**结果：连续两次 145/145，门禁恢复确定性。**

### D7 · c1 闭环 E2E 断言写错（测试侧，非服务端缺陷）

**现象**：`[5] 12402 接取任务 FAIL | 期望=code=1 | 实际=code=0`（C3.2/C3.3 两次记为"测试账号怪癖"）。

**根因**：新角色由 `mission_rows()` 播种时**链头已置 status=1（进行中）**；
对在途任务再发 12402「接取」**本就应该被拒**（C3.2-C I1 防御性收紧：已在途 ⇒ code=0 `already accepted`）。
原断言期望 code=1，测的是服务端明确不提供的语义。

**修复**：按真实语义订正，并补正向覆盖：
- `12402 重复接取在途任务被拒(防刷)` ⇒ 期望 code=0 ✅
- `12402 重复接取已完成任务被拒`（status=3）⇒ 期望 code=0 ✅

## 3. GM 后台管理系统

### 3.1 架构决策

**不新建服务**：复用 `mock_server` 既有 HTTP 8080 与 `Handler._send`，
在 `do_GET` 顶部一行接入 `gm.console`。控制台是**单文件 HTML SPA，零构建、零依赖**。

**规避循环 import**：`gm/console.py` **不** `import mock_server`；需要主机侧能力
（`push_to_rid` / `pack_frame` / `build_10201` / `scene_*`）时，由 `mock_server` 把**自身模块对象**作为 `host` 传入。

**写操作纪律**：写端点一律走既有正式链路（`gm.service` → `currency.service` / `growth_target` 等），
不直改业务表；唯一的直写是 `setscene` 的场景坐标（无 Service 覆盖），且显式落 `gm.log` 审计。

**鉴权**：`DSH_GM_TOKEN` 环境变量，缺省 `dshgm`；**仅写操作**校验，
只读端点沿用历史无鉴权现状（S3-L8，内网私服）。

### 3.2 新增端点

| 端点 | 类型 | 说明 |
|---|---|---|
| `GET /GM` | 页面 | 后台界面（11 个页签） |
| `GET /GM/api?act=overview\|roles\|rolecard\|online\|gmlog\|token` | 只读 | 聚合读接口 |
| `GET /DSH_ADMIN/roles\|accounts\|online\|gmsessions\|gmlog\|rolecard\|rolemail` | 只读 | 管理面 |
| **`GET /DSH_ADMIN/setscene?rid=&scene=&x=&y=&token=`** | **写** | **GM 传送**：写 `roles.scene_id/x/y` + **同步 `_last_enter`** + 推 `10200`/`10201`；x/y 省略用目标图 `def_x/def_y` |

> `setscene` 里"同步 `_last_enter`"是关键：`push_to_rid` 只发字节、不改 handler 状态，
> 而 `_current_bid()` 以 `_last_enter` 为准。不同步 ⇒ 传送后移动校验仍按旧图（就是 D1 的现象）。

### 3.3 页面（11 页签）

总览 / 角色管理 / 资产·等级 / 物品发放 / 邮件 / 任务 / 场景·副本 / 养成系统 / 审计日志 / 配置表 / 高级调用。

「高级调用」可直呼任意 `/DSH_ADMIN/<act>`，覆盖长尾系统（法宝/翅膀/神器/命格/坐骑/宗门/投资…），
不必为每个系统写专用表单。
