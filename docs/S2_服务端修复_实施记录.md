## 1. 项① 技能默认 tab 天赋列表（CS_10650）

### 改动
文件 `server/mock_server.py`：

1. **新增模块级 talent 加载器（L2108–L2135）**
   - `TALENT_CFG_PATH = .../cfg/config_skill_talent.json`
   - `_TALENT_LIST_CACHE` 模块级缓存；`load_talent_list()` 打开 JSON、取 `SkillTalent` 表、遍历每行读 `v['hash']['bid']`，收集 `0 < bid <= 0xffff` 的唯一 bid、排序返回。
   - **wire id 口径（关键取证结论）**：解构 JSON 的 dict key 与行内字段有 41 行错位，且 7 个 key（90200..90800）> uint16 上限 65535。经核对 `TalentRune.<group>.level.talent_id` 引用值（如 `TalentRune[15700].1.talent_id=40020` = 施毒一阶 bid；`TalentRune[50062].1.talent_id=50080` = 烈焰天罗一阶 bid），确认 **wire talent_id = 行内 `bid` 字段**。105 个 bid 全唯一、范围 10020..50082、全部 ≤65535，可安全 uint16 编码。
   - **决策：全量 105 个 bid（私服界面恢复，全部天赋置已解锁）**，不做解锁子集。依据：私服目标是把界面数据填实，且三源（fields.json / proto_defs / APK luac）对 10650 仅规定 `talent_list:table{id:uint16}`、无"按 group 过滤"字段。

2. **10650 handler（L17180–L17191）**
   - 由 `tl = self.cfg.get('talent_list') or []` 改为 `tl = self.cfg.get('talent_list') or load_talent_list()`；
   - 编码 `out = w_u16(len(tl)) + b''.join(w_u16(int(t) & 0xffff) for t in tl)`。
   - 帧体 = 2 + 105×2 = **212 字节**（含帧头总长 218 字节）。

### 原因 / 字段证据
- S2-A 取证：`config.json` 原本无 `talent` 键 ⇒ 10650 恒回空表（`tcp_prev*.log` 全是 `talent_list=0 (8 bytes)`）。
- 三源一致：fields.json `SC_10650 = talent_list:table{id:uint16}`（`cmd_resolve_106.luac`）；CS_10650 空请求。
- `cfg/config_skill_talent.json` 与 APK 解构 IDENTICAL（SkillTalent 105 条）。
