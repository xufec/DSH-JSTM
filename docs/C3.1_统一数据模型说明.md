## §1 权威来源总表

> 列定义：字段域 = 用户概念分类；权威表 = SQLite 中该字段的真值所在表；字段 = 实际列名；内存对象 = 请求处理时拼装的 Python dict；推送协议 = 下发到客户端的帧号；读写入口 = 业务模块函数；已知漂移 = 与权威不一致的旁路 / 双写残留。

### 1.1 身份类（rid / uid / name / level / career / sex / scene / x / y / vip_level / title / status）

| 项 | 内容 |
|---|---|
| 权威表 | **roles 表**（`persistence/db.py:63`） |
| 字段 | rid, uid, name, level, exp（注：exp 双写见 1.2）, career, sex, scene_id, x, y, dir, vip_level, title, status, is_online |
| 内存对象 | `role_state(cfg)` 合并链：ROLE_DEFAULTS ← cfg['role'] ← roles 行 ← role_assets（后者覆盖前者）（`role/storage.py:135-168`） |
| 推送协议 | SC_10301（122B，基础段，无 power 无 attr）；SC_1110（角色列表，30B） |
| 读写入口 | 读：`account/service.py:96 handle_1110` / `:122 handle_10101`；写：`gm/service.py set_level`（仅 level）；建角：`account/service.py` db_create_role |
| 已知漂移 | ① `roles.gold` / `roles.diamond` / `roles.coin` 列存在但**不是权威**（被 role_assets 覆盖），属历史双写残留（见 1.2）；② `self.cfg['role']` 浅拷贝隐患（`mock_server.py:16031-16034`，A §2 P5） |

### 1.2 货币 / 资产类（gold / coin / coupon / diamond / exp / vitality / sinew / practice_exp / rainbow_diamond / ...）

| 项 | 内容 |
|---|---|
| 权威表 | **role_assets 表**（`persistence/db.py:97`） |
| 字段 | rid, gold, coin, coupon, diamond, exp, vitality, sinew, practice_exp, rainbow_diamond, ... |
| 内存对象 | `role_state(cfg)` 合并时 role_assets **覆盖** roles 同名列（`role/storage.py:151-152`） |
| 推送协议 | SC_10302（128B，lev + 28×u32 + 尾 diamond/rainbow_diamond）；SC_10305（58B，资产增量，含 practice_exp） |
| 读写入口 | 读：`currency/service.py db_get_assets(rid)`；写：`currency/service.py db_add_assets(...)`；GM：`gm/service.py set_assets` / `set_diamond`；商城扣费：`mock_server.py:4472 shop_try_buy`；经验双写：`mock_server.py:6177-6182 add_role_exp`（roles.exp + role_assets.exp 同步） |
| 已知漂移（**关键**） | ① **diamond 双路漂移**（A §2 P1）：roles.diamond=0（stale）vs role_assets.diamond=100000（权威）；setdiamond 只写 role_assets，从不回写 roles.diamond；② **gold 双路已漂移**（A §2 P2）：roles.gold=1800140 vs role_assets.gold=1800041，差 99（S2 商城购买定情玉镯有意消耗）；shop_try_buy 只 db_set_assets({pay:...})，从不回写 roles.gold；③ **exp 双写已同步**（A §2 P3）：roles.exp=14439 == role_assets.exp=14439（add_role_exp L6182 双写）；④ **coin 双写已同步**：roles.coin=9907209 == role_assets.coin=9907209；⑤ **商城 💎 位实读 gold**（S2 §1.2）：商城 pay_type=1 → gold，diamond 未在商城扣款链路生效 |

### 1.3 战斗属性类（strength / intellect / armor / hp_max / atk_s / atk_m / def_s / def_m / hit / dodge / crit / anti_crit / mspd / ... 24 项）

| 项 | 内容 |
|---|---|
| 权威表 | **role_attr 表**（`persistence/db.py:78`） |
| 字段 | rid, attr_key, attr_value（键值对展开为 24 项） |
| 内存对象 | `attr_dict = ATTR_DEFAULTS ← cfg.attr ← db_get_attr(rid)`（B §2.2） |
| 推送协议 | SC_10303（204B，身份 + 12×u32 资产 + skill_list + power + 24 项 attr 大表）；SC_10306（88B，4×u16 + 12×u32 + 4×u16 + 4×u32 + mspd + power） |
| 读写入口 | 读：`attribute/service.py db_get_attr(rid)`；战力计算：`attribute/service.role_power()` = `power_mod.calc_power(attr_dict)`（非 config.json 硬编码，B §2.2 实证 power=724112）；写：属性变化入口散在 mock_server.py 旧 if 链（具体函数 UNKNOWN） |
| 已知漂移 | ① 10301（122B）**无 power 无 attr**（B §2.2），冷启动下 RoleVo.power=0；② 10303 / 10306 power 同源（role_power()），但 10306 在登录风暴中客户端**从未主动请求**（B §2.1），仅靠 S1 心跳补推 |

### 1.4 任务类（mission_bid / status / progress / ...）

| 项 | 内容 |
|---|---|
| 权威表 | **missions 表**（`persistence/db.py:89`） |
| 字段 | rid, bid, status（0=未接 / 1=已接 / 3=已提交）, progress, ... |
| 内存对象 | `role_state(cfg)` 不合并 missions；任务列表单独查 db |
| 推送协议 | SC_12400（42B，mission_list=1）；SC_12403（提交回包，code=1）；SC_12405（update_mission_list） |
| 读写入口 | 接取 12402 / 提交 12403：`task/service.py`（C §2 #5 实证 bid=10010 全 PASS）；进度推进：`mock_server.py:5066 mission_progress_advance`；幂等：`mock_server.py:16637`（status==3 直接回包不发奖） |
| 已知漂移 | ① **mission_progress_advance 无幂等**（A §2 P8d）：同一怪被杀两次加两次进度；② 12400 列表登录后 +12s 才补推（B §1.1 #32） |

### 1.5 背包 / 装备类（bag_items / equip_items / store_items）

| 项 | 内容 |

| 内存对象 | 不长期缓存；查询时现查 DB |

## §2 数据流图（文字描述）

### 2.1 上行：GM → Service → DB → 内存 → 推送 → 客户端

```
[HTTP /DSH_ADMIN/*]
    │  (mock_server.py:786 do_GET 路由)
    ▼
[gm/service.py] ──┬── set_level(rid, lev) ──→ UPDATE roles.level
                  ├── set_assets(rid, {key:val}) ──→ currency/service.db_add_assets(rid) ──→ UPDATE role_assets
                  └── set_diamond(rid, val) ──→ set_assets({diamond:val})
    │
    ▼  (写库后调 log_gm(action, rid, detail) → server/logs/gm.log)
[SQLite: server/state/roles.db]
    │  (roles / role_assets / role_attr / missions / bag_items / equip_items / ...)
    ▼
[内存 role_state(cfg)]  ← 每次请求现查现拼，无长期缓存
    │  合并顺序：ROLE_DEFAULTS ← cfg['role'] ← roles 行 ← role_assets（后者覆盖）
    ▼
[推送帧]
    ├── SC_10302（资产：lev + gold/coin/diamond/exp/...）
    ├── SC_10303（属性大表 + power + skill_list）
    ├── SC_10306（attr_table + mspd + power）
    ├── SC_10305（资产增量）
    └── 排程 S1 补推（10300 后排程 +5s，心跳 1199 触发）
    │
    ▼
[客户端]
    ├── RoleVo（initAttributeData / initRoleBaseData / updateRoleAllAttr）
    ├── HUD（直读共享 vo：DSH 724112）
    └── 面板（打开时一次性快照 vo.power；活刷新有 bid 门槛，自我角色不通过）
```

## §3 一致性与幂等现状

### 3.1 一致性现状（A 分片 11 条问题的归类）

| 类别 | 条目 | 现状 |
|---|---|---|
| **双路存储漂移** | P1 diamond / P2 gold / P3 exp-coin 模式不统一 | diamond/gold 已漂移（role_assets 权威，roles stale）；exp/coin 双写同步；无统一权威来源注释表 |
| **登录时序** | P4 首推 10302 不含 diamond（值=0）；P5 浅拷贝隐患 | S1-B 补推已解决 diamond 闪变（+5s 心跳触发，实测 +10s 对齐）；浅拷贝是防御性隐患 |
| **重登 / 重启** | P6 重登丢失 / P10 重启恢复 | **未发现问题**（所有字段落 SQLite；E2E 第 9 环实证） |
| **GM 直写** | P7 20+ admin 直写 DB 无审计 | 半 Service 化：3 条核心走 gm.service，20+ 条直写 |
| **幂等** | P8 发奖幂等不统一 | 12403 有 / shop_try_buy 有 / mission_progress_advance 无 / mail/addbag 无 |
| **绑定** | P9 rid/uid 绑定 | 10102 有归属校验；无 token 鉴权（私服可接受） |
| **schema 升级** | P11 旧库补列不统一 | 部分表 ALTER 幂等、部分没有 |

### 3.2 幂等现状明细（A §2 P8）

| 发奖点 | 是否幂等 | 机制 | 证据 |
|---|---|---|---|
| 任务提交 12403 | ✅ 有 | status==3 直接回包不发奖 | mock_server.py:16637；C §2 #10 重交 gold 5000→5000 不变 |
| 商城购买 shop_try_buy | ✅ 有 | reward.grant(reference_id='shop:gid:rid:seq') | mock_server.py:4476；reward/service.py:51 |
| 任务进度 mission_progress_advance | ❌ 无 | 同一怪被杀两次加两次进度 | mock_server.py:5066 |
| 邮件附件领取 | ❌ 无 | 未走 reward.grant | A §2 P8c |
| GM addbag | ❌ 无 | 可反复刷道具 | A §2 P8c |
| reward_log 表存在 | — | persistence/db.py:105；但未被所有发奖点使用 | A §2 P8c |

### 3.3 最小修复建议（引用 A §2 P8，只列不实施）

1. **统一货币权威来源**：废弃 roles.gold/diamond/coin 列，所有读走 role_assets（或所有写点双写同步，仿 add_role_exp L6182）；
2. **setassets 补负数校验**：`gm/service.set_assets` 加 `amount>=0` 与货币上限校验（C §5 #1）；
3. **admin 命令统一审计**：do_GET 入口包一层审计中间件，所有写库 action 一律 log_gm()；
4. **发奖统一走 reward.grant**：mission_progress_advance 加 (rid, cond_name, target, ts-window) 幂等键；mail 附件 / addbag 走 grant；
5. **统一 migration 框架**：所有新增列的表建立 `_ensure_columns(con, table, {col: default})` 幂等函数；
6. **权威来源注释表**：在 role/storage.py 顶部加注释表（主列字段→roles；其余货币/资产→role_assets），防止新增字段时误写。
