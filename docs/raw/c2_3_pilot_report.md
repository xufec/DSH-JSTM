## a) 任务"详情"按钮无响应

- **复现**：任务面板 → 点 (1240,515)/(1180,515) 共 3 次（`a_detail_tap1.png`/`a_detail_tap2.png`/`a_detail_tap3.png`），面板无任何变化。
- **tcp.log 证据**：三次点击期间只有心跳帧，零业务 `>> cmd=`。
- **静态证据**：`_mission_view2_dis.txt`（92KB）——面板只绑 quit_btn（X）与 sure_btn（动态标签：立即传送/放弃任务/提交）两个可点按钮；`'详 情'`（带空格）来自 `createTitle(right_container, '详 情', 38, 316)`，是右容器的**静态节标题文字**，全文件无任何 touch listener 指向它。
- **根因**：盘点把装饰性节标题误判为按钮；客户端无缺注册/缺 handler，无坐标点错。
- **影响范围**：无。任务面板功能正常。
- **修复方案**：无需修复；仅修正盘点文档（把"详情按钮 EXISTS_BROKEN"降级为"静态装饰文字"）。

## b) 回城按钮 BLOCKED

- **复现**：城内地图打开 → 点回城 (2169,719) 两次（`b_citymap_open.png`/`b_returncity_tap1.png`/`b_returncity_tap2.png`），无响应、绿点不动。
- **tcp.log 证据**：两次点击零 CS。
- **静态证据**：`_map_preview_dis.txt` —— btn_city handler = `SceneController:getInstance():gotoScene(10001)` 硬编码回城场景号。
- **tcp.log 确认**：当前场景 bid=10001（17:39:41 SCRoleEnter）。
- **根因**：客户端已在目标城 10001，`gotoScene` 命中 already-in-scene 自我抑制 → 不发 CS、无效果。非服务端 handler 缺失（mock_server 10206 寻路应答、10205 Teleport 均已实现）。
- **影响范围**：城内无法触发回城视觉，但无实际功能损失。
- **修复方案**：客户端行为本身合理；要验证回城协议链路需先出城（世界地图传送本身 UNKNOWN，下阶段处理）。

## c) 日常活力 ?????/?????

- **复现**：任务面板 → 日常 tab（`c_daily_tab.png`）：顶部活跃度 `?????/?????`，列表项本地 config 渲染正常。
- **tcp.log 证据**：本会话全程（16:53→17:53+）grep 13781/13786/13787/13789 **零命中**——客户端从未发请求。
- **静态证据**：`_daily_ctrl_dis.txt`（66KB）——on13781/on13786 已注册；proto#8 = `if not arg: self:initConfig(); SendProtocal(GetPrototype(13781))`（请求函数）；mission_view2 无任何 13781/huoli 引用——日常 tab 只渲染本地任务列表，顶部活力标签等 daily_ctrl 的 vitality_event 事件。服务端 mock_server.py:18820 已完整实现 R48：CS_13781(空)→SC{total_val, huoli_list{id,num,val}, lingqu_list}；CS_13786(空)→SC{week, richang_list{id,num}}。
- **根因**：客户端本会话从未触发 13781/13786 请求（日常 tab 打开不发请求；独立 daily 面板入口未定位到），服务端 handler 就绪但无请求可应 → 标签停在占位符。

## d) F1 传送后 HUD 战力归零

- **复现**：本会话基线 HUD 战力已=0（盘点会话遗留，`00_env_now.png`）；期间客户端 17:39:12 断连、17:39:35 自动重连，完整登录风暴被 tcp.log 捕获。
- **tcp.log 证据**：17:39:39 << SC_10303 attr（204 字节，含 power）→ 17:39:41 << SC_10301（122 字节，initRoleBaseData 重建 vo）——**10303 在 10301 之前**，与 C2.2 F1 时序同源。重连后 HUD=0 持续；手动重开角色面板（`d_charpanel_open.png`）显示**综合战力=724112**（setData 直读 vo.power，正确）。
- **根因**：HUD 战力标签是事件驱动刷新；10301 重建 vo 瞬间 power=0 的事件把 HUD 刷成 0，之后服务端无收尾 10303/10306 重推 → HUD 定格 0；面板重开时直读 vo 所以正确。
- **影响范围**：仅 HUD 顶栏战力数字显示；真实战力 vo=724112 正确，所有读 vo 的面板均正确。
- **修复方案**：**与 C2.2 方案 C 合并**——任务推进/场景风暴收尾后服务端补推 10303/10306（待服务端）。G7 同源问题，无需第二套修复。

## e) 挂机图标/活动顶栏随相机消失

- **复现**：滑动相机两次（swipe 1280,800→600,800）后截图对比（`e_baseline_nopan.png`/`e_camera_pan1.png`/`e_camera_pan2.png`/`e_camera_pan_back.png`）：固定 HUD（首充1160/变强1248/挂机1320、左列排行榜/钻石VIP/好友、右列任务/队伍、底栏）位置不动；**限时返利(1395,100)/玩家回归(1467,100) 两个活动图标在相机平移后消失，滑回来后复现**——世界坐标锚定节点。
- **挂机按钮点测**：(1320,100) 点测（`e_hangup_tap.png`）无面板弹出、tcp.log 无新 CS（仅 10204 移动帧与心跳）——挂机入口 BLOCKED（疑 config_function 门禁静默拦截）。
- **根因**：活动图标（限时返利/玩家回归）绑定世界坐标而非屏幕层，相机平移即离屏；挂机入口另有门禁静默拦截。
- **影响范围**：活动入口在相机偏移时不可见（但可滑回复现）；挂机面板本就 BLOCKED。
- **修复方向**：客户端渲染配置（活动图标改绑屏幕层），不需服务端；挂机门禁下阶段另查。本阶段不实施。

## f) 购买确认链路

- **复现（盘点证据 + 本会话静态/log 闭环）**：
  - 盘点 `36_mall_changyong.png`（商店面板：购买绿色按钮右下；商品 定情玉镯99钻/绫罗缎45/洗髓丹5；拥有 1800140）→ `38_mall_buy_confirm.png`（点购买后无确认弹窗、商城关闭）。
  - 本会话：商城是世界锚定浮动节点，重连后多次变换相机/走回喷泉均未重新定位到商城入口节点（`f_mall_try2.png`/`f_mall_try3.png`/`f_walk_nw.png`/`f_search_left.png`），**未能现场重开商城复现点击**——如实记录此阻塞。
- **tcp.log 证据**：grep 12805/12832/12837/12839/12843/13402 **全程零命中**；gold=1800140 未变（17:39:41 DB persist，多次校验一致）。商城商品 CS_13806 仅在登录风暴自动请求（16:55:32/17:39:41 各一次，SC goods_list=1），面板用缓存商品渲染。
- **静态证据**：`_shop_normal_view_dis.txt` buyGoods(id,num) 完整反汇编——链路为：
  ```
  if num==nil or selectItem==nil: return
  if nextLevShow(宗门等级不足): 提示, return
  if 余额不足(pay_type, price*num): return        ← 静默 return，无提示
  if type==WEEKDAY: 限购校验 → request12832(id,num)
  elif type==ZHENBAO: 限购校验 → request12837(id,num)
  elif type==NPC: subType==SECRET→request12839 / SECRET2→request12843
  else: ShopCtrl:buyGoods(id,num)
  ```
  全链路**无 common_alert 确认弹窗**（原版设计=点购买直接发 CS）。
- **根因**：buyGoods 在发 CS 之前先做本地余额校验；本会话钻石=0（HUD 右上 0），商品价 99 钻 → 校验失败 → **静默 return**：无弹窗、无 CS、无扣款。不是"客户端少弹确认"（原版就没弹窗），也不是"服务端直接扣款"（根本没收到 CS）。
- **影响范围**：商城购买在当前资产态下全部静默失败；gold（金币 1800140）与钻石（0）显示口径不一致——商城"拥有"栏读的是金币字段而非钻石字段，也是本地校验失败的旁证。
- **修复方案（待服务端）**：补推钻石资产（SC_10305 资产包补钻石字段 / 登录风暴资产补齐），使客户端本地钻石余额>0、校验通过、buyGoods 正常发出 request12832。服务端 shop_try_buy（mock_server.py:4361，选币→限购→扣费→发货→记限购）已完整实现，收到 CS 即可闭环。
