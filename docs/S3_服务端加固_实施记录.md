## ① setassets 校验 + admin 集中审计挂钩

### 改动 1a：setassets 负数校验
- **文件+行号**：`server/mock_server.py` L1738-1745
- **代码**：
  ```python
  # ★ S3-A 任务2（G1）：setassets 负数/非法值校验——对齐 setlevel(1..200) 与 setdiamond(val>=0)。
  for _k, _v in vals.items():
      if _v < 0:
          return self._send(400, json.dumps(
              {'ok': False, 'error': '%s must be >= 0 (got %d)' % (_k, _v)},
              ensure_ascii=False))
  ```
- **原因**：原实现 `setassets?rid=1001&gold=-100` 直接落库（C3.1 台账 T3 / A 分片 §3.3 实证）。补防御性校验，与 setlevel/setdiamond 对齐。
- **证据（实机 curl）**：
  - `GET /DSH_ADMIN/setassets?rid=1001&gold=-100` → **HTTP 400** `{"ok": false, "error": "gold must be >= 0 (got -100)"}`；DB gold 未变（仍 1800041）。
  - `mode=add gold=100` 允许（→1800141）；随后 `mode=set gold=1800041` 恢复基线。
- **验证结果**：PASS（见测试报告 §1.3）。

### 改动 1b：admin 写命令集中审计挂钩

## ③ 击杀块 mission_progress_advance 幂等门控

- **文件+行号**：`server/mock_server.py` L9925-9948
- **关键代码**：
  ```python
  _kill_gr = grant(rid, _awards, reference_id='kill:%d:%d' % (mon_bid, rid), source='battle')
  ...
  # ★ S3-A 任务3（G4）：与击杀奖励同一幂等键——同一 mon 的重复结算
  #   （重放/重入）奖励已被 reward_log 拦截，进度推进必须同步跳过。
  if not _kill_gr.get('already'):
      prog = mission_progress_advance(rid, 'fight_mon', mon_bid, 1)
      ...push 12405...
  ```
- **原因**：原实现击杀奖励已走 reward.grant（reward_log PK 幂等），但 mission_progress_advance 原本**无条件执行**——同一怪重放/重入会出现"奖励不重复、进度却 +N"的不一致（C3.1 T8 / A 分片 §2 P8d）。
- **幂等机制**：reward/service.py `grant()` 第 57-58 行——`reward_log(rid, reference_id)` 命中即提前返回 `{already:True, applied:[]}`，不重复发奖；reward_log 主键 `(rid, reference_id)`。
- **确定性验证**（重复提交同一次击杀）：
  - 已存在 `reward_log` 行 `kill:20001:1001`（source=battle）。
  - 再次 `grant(1001, [{asset:gold,9999}], 'kill:20001:1001')` → 返回 `{ok:True, already:True, applied:[]}`。
  - gold 1799942 不变、exp 14439 不变、reward_log 行数 10 不变。
- **验证结果**：PASS（机制确定性证明）。注：野外交互战斗双杀重放因城内无可击杀怪未能在本会话实机触发，详见测试报告 §1.5 NOT_RUN 说明。
