## §2 诊断过程摘要（a-f 六项结论 + 修正）

> 全部引自 `docs/_raw/c2_3_pilot_report.md`；本节为收尾整合口径，不重复反汇编细节。

### a) 任务"详情"按钮 —— **盘点误判，非缺陷，无需修复**

- 复现：任务面板点 (1240,515)/(1180,515) 共 3 次，面板无变化，tcp.log 仅心跳帧。
- 静态根因（`_mission_view2_dis.txt` 92KB）：面板只绑 quit_btn(X) 与 sure_btn（动态标签：立即传送/放弃任务/提交）两个可点按钮；`'详 情'`（带空格）来自 `createTitle(right_container, '详 情', 38, 316)`，是右容器**静态节标题装饰文字**，无 touch listener。
- **修正**：G2 从接口缺口清单移除；盘点"详情按钮 EXISTS_BROKEN"降级为"静态装饰文字误判"。任务面板族整体 VERIFIED_WORKING。

### b) 回城按钮 BLOCKED —— **行为合理，需出城才能验证**

- 复现：城内地图点回城 (2169,719) 两次，无响应、绿点不动。
- 静态根因（`_map_preview_dis.txt`）：btn_city handler = `SceneController:getInstance():gotoScene(10001)` 硬编码回城场景号。
- tcp.log 确认：当前场景 bid=10001（17:39:41 SCRoleEnter），已在目标城 → gotoScene 命中 already-in-scene 自我抑制 → 不发 CS、无效果。
- **修正**：BLOCKED 改标"合理行为"；回城链路本身（CS_10200→:15957、10205 Teleport、10206 寻路应答）服务端已实现；要验证回城协议需先出城（依赖 G8 世界地图传送接线）。

### c) 日常活力 ?????/????? —— **客户端从不发 CS_13781/13786，待服务端补推**

- 复现：任务面板→日常 tab，顶部活跃度 `?????/?????`，列表项本地 config 渲染正常。
- tcp.log：本会话全程（16:53→17:53+）grep 13781/13786/13787/13789 **零命中**。
- 静态根因（`_daily_ctrl_dis.txt` 66KB）：on13781/on13786 已注册；proto#8 = `if not arg: self:initConfig(); SendProtocal(GetPrototype(13781))`（请求函数）；mission_view2 无 13781/huoli 引用——日常 tab 只渲染本地任务列表，顶部活力标签等 daily_ctrl 的 vitality_event 事件。服务端 mock_server.py:18820 已完整实现 R48（CS_13781→SC{total_val, huoli_list, lingqu_list}；CS_13786→SC{week, richang_list}）。
- **修正 G6**：原盘点猜"10301 推送链缺活力字段"——错误。真实数据源是 13781/13786；客户端从未触发请求，服务端 handler 就绪无请求可应。修复方向：**待服务端**登录风暴收尾主动补推 SC_13781+13786，客户端 on13781/on13786 已就绪可直接消费。

### d) HUD 战力归零（F1 扩写）—— **与 C2.2 方案 C 合并**

- 复现：本会话基线 HUD 战力已=0；17:39:12 断连、17:39:35 自动重连，完整登录风暴被 tcp.log 捕获。
- tcp.log：17:39:39 << SC_10303 attr（204 字节，含 power）→ 17:39:41 << SC_10301（122 字节，initRoleBaseData 重建 vo）——**10303 在 10301 之前**，与 C2.2 F1 时序同源。重开角色面板（`d_charpanel_open.png`）显示综合战力=724112（setData 直读 vo.power，正确）。
- 根因：HUD 战力标签事件驱动刷新；10301 重建 vo 瞬间 power=0 的事件把 HUD 刷成 0，之后无收尾 10303/10306 重推 → HUD 定格 0；面板重开直读 vo 所以正确。
- **修正 G7**：与 C2.2 方案 C 合并——任务推进/场景风暴收尾后服务端补推 10303/10306（待服务端）。G7 同源问题，无需第二套修复。

### e) 活动图标随相机消失 —— **世界锚定节点，客户端渲染配置改绑屏幕层（不实施）**

- 复现：滑动相机两次（swipe 1280,800→600,800）对比：固定 HUD（首充1160/变强1248/挂机1320、左列排行/钻石VIP/好友、右列任务/队伍、底栏）不动；**限时返利(1395,100)/玩家回归(1467,100) 两个活动图标在相机平移后消失，滑回复现**——世界坐标锚定节点。
- 挂机按钮点测（(1320,100)）：无面板弹出、tcp.log 无新 CS（仅 10204 移动帧与心跳）——挂机入口 BLOCKED（疑 config_function 门禁静默拦截）。
- **修复方向（本阶段不实施）**：客户端渲染配置——活动图标改绑屏幕层（不需服务端）；挂机门禁下阶段另查。

### f) 购买无确认弹窗 —— **buyGoods 本地余额校验静默 return；原版无二次确认弹窗；待服务端补推钻石资产**

- 复现（盘点证据 + 静态/log 闭环）：盘点 36_mall_changyong.png → 38_mall_buy_confirm.png（点购买后无确认弹窗、商城关闭）；本会话重连后多次变换相机/走回喷泉均未重新定位到商城入口节点，**未能现场重开商城复现点击**——如实记录此阻塞（R1）。
- tcp.log：grep 12805/12832/12837/12839/12843/13402 **全程零命中**；gold=1800140 未变（17:39:41 DB persist，多次校验一致）。
- 静态根因（`_shop_normal_view_dis.txt` buyGoods 反汇编）：链路为 `num==nil/selectItem==nil → return` → `nextLevShow(宗门等级不足) → 提示 return` → **`余额不足(pay_type, price*num) → 静默 return`** → 再按商品类型发 12832/12837/12839/12843/ShopCtrl:buyGoods。全链路**无 common_alert 确认弹窗**（原版设计=点购买直接发 CS）。
- 根因：本会话钻石=0（HUD 右上 0），商品价 99 钻 → 本地余额校验失败 → 静默 return：无弹窗、无 CS、无扣款。不是"客户端少弹确认"（原版就没弹窗），也不是"服务端直接扣款"（根本没收到 CS）。
- **修正 G1**：原 G1"购买确认弹窗未弹"——误判。原版 buyGoods 本就无二次确认弹窗；真实缺口是**钻石资产=0 导致本地校验静默失败**。修复方向：**待服务端**补推钻石资产（SC_10305 资产包补钻石字段 / 登录风暴资产补齐），使客户端本地钻石余额>0、校验通过、buyGoods 正常发出 request12832。服务端 shop_try_buy（mock_server.py:4361，选币→限购→扣费→发货→记限购）已完整实现。
