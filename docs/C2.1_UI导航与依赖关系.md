## §4 最小改动方案建议（基于勘查报告 R1–R7 与框架机制）

1. **切入点**：`assets/src/game/main/view_manager.luac`（面板挂载/关闭统一模板）+ `assets/src/game/nav/nav_secondary_menu.luac`（主界面按钮→二级面板跳转注册表）——两者为 C2.1 改动面最小、证据最硬的模块（survey §5.1 第4问结论）。
2. **重打包链路（唯一通道，R1）**：改 luac → `tools/patch_fake_login.py`（当前运行包链：DEX is_close 单字节 + config.luac 末尾注入 Lua）→ zipalign → apksigner（dsh.keystore）→ `adb install`。**不存在免重打包的运行时热改**：当前运行包（jstm_1411_fakelogin_aligned.apk）无 dsh_patch.lua 热补丁加载器；写可目录 config.luac 覆盖已实测无效（patch_apk.py 注释）。若需等长替换 `.so` URL，遵守 patch_apk.py `fit()` 等长约束。
3. **运行时探针风险（R2）**：observer/热补丁块在联调模式实测卡死启动（网络异常/下载循环）；C2.1 若需运行时探针，先做 observer 解耦（lua_injection_round2.md §六方案 A+B），不要直接往当前运行包加注入块。
4. **已知缺陷防踩（R3）**：role ctrl 综合战力=0（D1）、backpack 10502 已发 4 件但 UI 显示 0/150（D2）是既有缺陷，复原时勿误判为"复原失败"重复踩坑；先看 runtime_findings.md 与 d2_rootcause.md。
