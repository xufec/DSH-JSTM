# 50 轮目标 · Round 11（goal round 29）—— 否证"任务奖励含物品"；并发现一个**资产码陷阱**

> 时间：2026-10-01 ｜ 本轮目标：找本作**真实物品来源**（用于验证"掉落进包"环）

---

## 〇、一句话结论

> 把 846 条任务的全部 `award_assets` 展开统计后，**奖励资产码只有 4 种**：
> `4`（279 次）、`2`（278 次）、`15`（262 次）、`3`（231 次）—— 全部是**货币/经验**类
> （对应 `ASSET_CODE`：2=coin、3=coupon、4=exp、15=hero_exp），**没有任何物品奖励**。
> ⇒ **"任务奖励是真实物品来源"这条假设被否证**（至少在 1.4.9 的 846 条任务里）。
> 同时发现一个**必须记录的陷阱**：小数字资产码（2/3/4/15）**与物品 bid 空间撞号**
> （例如 `item_config.json` 里确实存在 bid=2/4 的条目）⇒
> **"某码在物品表里存在"不能用来判定它是物品码**（我本轮第一次统计就差点据此误判）。

## 一、本轮实测

```
奖励资产码分布（846 条任务的全部 award_assets 展开）:
  code=4    279 次        ← exp（经验）
  code=2    278 次        ← coin（银魂币）
  code=15   262 次        ← hero_exp（魂师经验）
  code=3    231 次        ← coupon（金魂币）
（没有第 5 种码；也没有 code=1 gold）
```

**结论**：任务奖励 = **纯货币/经验**，**不含物品**。
⇒ 想验证"`10500` 掉落进包"这条环，**不能**靠任务奖励；
也再次说明 `Config.Drop`（唯一带物品的表）不可用（前两轮已否证其属本作）。

## 二、★ 本轮的方法学产出：资产码撞号陷阱

| 事实 | 说明 |
|---|---|
| 现象 | `item_config.json` 里存在 `bid=2`、`bid=4` 等**极小 bid** 的条目 |
| 陷阱 | 于是"某资产码在本作物品表里存在"这个判据**恒为真**（2/3/4/15 都能"命中"），**毫无鉴别力** |
| 正确判据 | 判定一个 `award_assets` 码的语义，只能靠：① `analysis/` 里的**界面读数/实机反证**；② 该码在**大范围**（如 3xxxx/5xxxx 段）且与已知货币码不冲突 |
| 已记录 | 本报告 + 上一轮 README §5.3 的证据等级纪律（不靠"配置里写着"） |

> 我本轮第一次统计时确实打印了"code=4 → 在本作物品表: 是"，**那是撞号假象**；
> 随即用"码只有 4 种且与货币语义完全吻合"这一更强证据推翻了它。
