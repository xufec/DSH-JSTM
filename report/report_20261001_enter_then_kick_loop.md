## 〇、一句话结论

> 最小探针下，客户端**并不是"卡在登录"**，而是：
>
> ```
> 服务端推送计数: {1110: 935, 10102: 926, 10200: 925, 10201: 925, 1199: 75, 10502: 13, …}
> 客户端首次发出的命令（全部集中在 21:02:08 同一秒）:
>   10001 → 1110 → 10103 → 10999 → 10300 → 10800 → 13300 → 10923 → 10502 → 10301
>   → 10922 → 10924 → 13200 → 20809 → 13321 → 11200 …
> ```
>
> ⇒ **`10200`（进场景）与 `10201`（场景格子）各被推了 925 次**，且客户端的
> `10300/10800/13300/10923/10502/13200/11200/20809` 等**典型"在图内才会发"的子系统轮询**同时出现
> ⇒ **它确实进了图，然后立刻掉线/重登，如此循环约 925 次/分钟**。
>
> ⇒ **"进不了图"应修正为"进得去但立刻被弹回、反复重登"** —— 这是**新问题**（之前被登录 UI 的假象盖住了）。
