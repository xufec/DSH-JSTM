> 时间：2026-10-01 ｜ 目标 APK 1.4.9 ｜ 本轮目标：用"全量包住所有 `WriteHeader` 宿主"的办法找出真实发送对象。

## 〇、一句话结论

> **上一轮的 `v43_socket=FOUND UserMsgAdapter` 是启发式误报，本轮被实测否证。**
> 依据（同一次运行内）：
> - 服务端**确实收到了** `10001 ×3、1110 ×3、1199 ×194`（客户端在发）；
> - 而全量扫描 `_G` 后，**唯一**被包到的宿主是 `UserMsgAdapter`（`v44_wrapped=UserMsgAdapter`，其它宿主数 = 1），
>   但 **`WriteHeader` 在这条路径上一次都没被调用**（无任何 `v44_wh` 输出）。
> ⇒ `SendProtocal` 用的 `WriteHeader` **不在任何 `_G` 全局上**；
> 结合反汇编（`GGET D=3 → TGETS 'socket'`），它读的是 **某个对象的 `.socket` 字段**
> （即"**字段里的对象**"，不是全局）——这就是扫描不到的原因。

## 一、本轮证据

### 1.1 客户端（`files/dsh_v44.txt`）

```
v44_wrap_all_hosts
v44_wrapped=UserMsgAdapter            ← 全量扫描只包到这一个宿主
v44_watch=n=20..160 已包宿主=1         ← 始终只有 1 个
（没有任何 v44_wh / v44_send 输出）
```

### 1.2 服务端（`logs/minloop/live11_stdout.log`，同一时间窗）

```
连接总数: 13 ｜ 命令: {1199: 194, 10001: 3, 1110: 3}
```
⇒ **客户端在窗口内确实发帧了** ⇒ "没有 `v44_wh`"**不是**因为客户端没发，
而是因为**真实宿主不是 `UserMsgAdapter`**。

### 1.3 反汇编给出的解释（第 19 轮已解出，本轮对上）

```
10  GGET   A=2 D=3          ; A2 = <全局 D3>
11  TGETS  A=2 B=2 C=4      ; A2 = A2['socket']     ← ★ 读的是**字段**！（不是我扫的全局）
16  GGET   A=2 D=7          ; 发送器全局
17  TGETS  A=2 B=2 C=8      ; A2 = A2['WriteBegin']
```
⇒ 发送用的对象来自 **`<某个全局>.socket`** ⇒ 我"只扫 `_G` 顶层"的做法**必然扫不到**。
