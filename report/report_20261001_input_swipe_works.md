# 「不能点击移动」续 —— ★ 发现：**拖动(swipe)能进游戏并触发协议，点击(tap)多数不能**

> 时间：2026-10-01 ｜ 前提：v51 已证明 `move()` → `CS_10204` **链路完全通畅**（问题在输入层）

---

## 〇、一句话结论

> ★ 本轮把"输入层"这一层**开了一个口子**：
> | 输入方式 | 结果 |
> |---|---|
> | **tap**（点 UI 节点，55 个坐标） | 只有 3 个触发命令（`10341` 朋友圈 / `10621` 技能 / `16900` 充值），**从不触发移动** |
> | **swipe**（拖动） | ★ **能触发协议帧**：`swipe 300,1250→620,1100` ⇒ **`10206` + `20100`**；另一条 ⇒ `10341/10999/30716` |
>
> ⇒ **这个客户端的移动是"拖动/摇杆"一类输入，而不是点 HUD 按钮**；我此前一直用 tap，所以"点了没反应"。
> 但**仍未找到**能触发 `CS_10204` 的那个手势/区域（下一轮用**网格扫描**解决）。

---

## 一、本轮实测

### 1.1 五条 swipe 的结果

```
swipe 250,1230 → 520,1030   → （无）
swipe 300,1250 → 620,1100   → ★ 10206, 20100
swipe 200,1200 → 460,1000   → （无）
swipe 1280,820 → 1500,700   → 10341, 10999, 30716
swipe 1280,900 → 1280,1100  → （无）
```

### 1.2 从 `300,1250` 出发的四方向复查

```
dir 300,1250 → 600,1250  → （无）
dir 300,1250 →  80,1250  → 10341        ← 打到 UI 元素了
dir 300,1250 → 300, 980  → （无）
dir 300,1250 → 300,1400  → （无）
```

### 1.3 触发的命令是什么（据 `protocol/fields.json`）

| 命令 | 规格 | 语义 |
|---|---|---|
| `CS_10206` = `x:uint32`（**只有一个参数**）／ `SC_10206` = `code,msg` | 单参 | **UNKNOWN**（移动家族，但非 10204 的 `x,y` 形态） |
| `CS_20100` = 无字段 ／ `SC_20100` = `power:table, promote:table` | 请求型 | 疑似面板/战力提升请求 |
| `10341` / `10621` / `16900` | —— | 朋友圈 / 技能 / 充值（与前几轮一致） |

> `10206` 与 `20100` 本服都**没有专用处理**（走通用应答）—— 但它们是"输入 → 协议"的**活证据**。

---

## 二、由本轮得到的判断

1. ★ **输入层并非"完全不通"**：swipe 能触发命令 ⇒ 合成输入**确实到达了客户端**并被处理。
2. ★ **"点击不能移动"的直接原因**：客户端移动用的是**拖动手势/摇杆**，而我一直用 `tap`。
3. ⚠️ 但 `10204` 仍未出现 ⇒ 我 swipe 的**起点/方向/时长**还没命中真正的移动控件
   （可能是摇杆的有效半径、或必须"按住-移动-抬起"且中间帧足够多）。
4. ★ 依据 v51：**协议与服务端**这一侧无需再查（`move()` 一调就发包、服务端逐帧 ack）。
