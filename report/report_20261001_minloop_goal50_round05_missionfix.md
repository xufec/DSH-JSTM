## 二、本轮修复（`server/minloop/min_loop_server.py::mission_target`）

```python
# 配置实际形态（任务 10020）：
#   "progress": [["fight_mon", 20001, 1], [0, 0, 20010, 0]]
#   行语义 = [类型名, 目标bid, 数量]
# 旧代码：if isinstance(p[0], dict) ... else return 0, 0   ← ★ 列表行被当成"无条件"
# 新代码：识别列表行并解析 fight_mon ⇒ (target=20001, need=1)
#          非 fight_mon 的行语义**未确证** ⇒ 不据此设门槛（标 UNKNOWN，不猜）
```

**影响面（诚实评估）**：这条 bug 只会让"有条件的任务"变得**过于宽松**（不需打怪即可提交），
不会造成崩溃或数据损坏；但它**破坏了回环语义**（"打怪 → 进度 → 提交"这一环形同虚设）。
