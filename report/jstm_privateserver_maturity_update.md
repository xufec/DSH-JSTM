## 二、★ 对上午版两处"硬阻塞"的**实证更新**

### 2.1 "进不了场景（`getScene()==nil`）" —— ⚠️ **已被实测推翻**

上午版 §八 称此为首要阻塞。**本版证据表明场景是能进的：**

| 证据 | 内容 |
|---|---|
| 服务端 | `<< 10200 SCMapGird (server push)` + `<< 10201 SCMapGird roles=1 npcs=26 mons=1 (654 bytes)` |
| 客户端包裹 | `SceneController.on10201_wrapped` → `in_npcs26_mons1_elems0` → **`after_npcList26_elemList0_monList1`** |
| 画面 | 多张截图可见 NPC（周漪/唐舞桐/霍雨浩）、角色（DSH）、地图建筑、任务栏 |
| 战斗 | 能对着**场景怪物 20001** 发起战斗并打完 |

**⇒ 结论：`getScene()` 在正确时序下**是有对象的**；上午版的 nil 判断要么是时序过早，要么是当时状态。**
**⇒ 场景门不再列为"硬阻塞"，降级为"已通，但需注意 `10201` 的时序（`on10201` 之前读容器会得到空）。**

### 2.2 "战斗画面不渲染" —— ⚠️ **流程层已全通；"是否渲染画面"仍未独立验证**

上午版称 `BattleView.loadBack/createUI` 从未被调用。**本版实测到的是**流程**全通：**

```
[18:53:19]  >> CS_20002 fight monster mon_id=20001
[18:53:19]  << 20002 SC_20002 code=1(TRUE) mon=20001 bid=20001 name=戴浩
[18:53:19]  << 20010 SC_20010 battle init fighters=2 mon_hp=2400 role_hp=4321
[18:53:22]  << 20012/20013 round=1 → role->mon hit=772 mon_hp=1628/2400
[18:53:24]  round=2 → mon_hp=856/2400
[18:53:27]  round=3 → mon_hp=84/2400
[18:53:29]  ** battle monster died, battle result=1
[18:53:29]  << 20020 SC_20020 result=1
[18:53:32]  << 20023 SC_20023 type=0 result=1 role_hurl=2
[18:53:32]  ** battle mission progress: fight_mon target=20001 -> [10020]   ← ★ 反哺任务
[18:57:29]  ** battle drop item=51038(酒剑仙灵魂玉) x2 -> bag item_id=1 quantity=6
[18:57:29]  << 10500 SC_10500 bag push bag_code=7 items=1                    ← ★ 掉落进包
```

**⇒ 战斗**数据链**：发起 → 回合循环 → 怪物死亡 → 胜负 → 结算 → 掉落进包 → **反哺任务进度**，全部实测成立。**
**⚠️ 但"战斗**画面**是否渲染"本版**未独立验证**（未截到战斗画面帧）⇒ 该点保持 `UNKNOWN`，不宣布已修复。**
**⇒ 因此本版把战斗的"流程"评为可用，把"画面"仍记为待验证。**

### ★ 本版特别记录的**一次自我否定**（体现数据纪律）

**曾判断"`Config.MonData.hp_num` 存在 ⇒ 怪物血量可校准"。**
**深入统计 7,956 条后否证**：`hp_num > 0` 的**只有 27 条**（99.7% 为 0）⇒ **它不是战斗血量。**
**⇒ 最终结论更正为：怪物战斗数值在 1.4.9 客户端配置里**不存在**，无法校准。**
（按项目规则，被否证的假设与更正过程**完整保留在案**。）
