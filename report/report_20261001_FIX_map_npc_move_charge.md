## 二、逐项排查证据

### 2.1 地图不清晰 —— 两条原因被**否证**

| 假设 | 检验 | 结果 |
|---|---|---|
| "缺场景/地图消息" | 统计参考服发出的 **所有** `102xx`：**只有 `10200 / 10201 / 10204`** | ❌ 否证（**与我完全一致**，没有别的场景消息） |
| "客户端取地图资源失败（我缺 `/cdn/*`）" | 扫我服务端的 HTTP 日志（live12/13/14）：**非探针请求只有 `POST /gateway/mobile/json`** | ❌ 否证（客户端**从不向我请求地图资源**） |

⇒ 地图数据来自客户端自身；"不清晰"更可能是**客户端地图渲染未初始化**。
**旁证（早前实测）**：可用会话里 `sceneData` 的 `mapResCache=192 / order=192 / nowPicTile=table`，
而我的会话一直是 **`mapResCache=0 / nowPicTile=nil`** ⇒ **UNKNOWN**：为何参考服会话能到 192。

### 2.2 没有 NPC —— 规格与真值都查了

- `SCMapGird_10201.npcs` item = `[id,bid,type,x,y,name,misc,animate_res,member]` ⇒ **没有 `res_id`**
  （NPC 外观由客户端按 `bid` 自取）⇒ 我发的 **19 个 `bid` 是真值**（来自 `_mapnpc_10001.json`），结构上无缺项。
- 但 `_mapnpc_10001.json` 里 **`name` 全为空**，`config_npc.json` 也只有 `face/button/dir/lev`（**没有 name**）
  ⇒ **NPC 真名来源 = UNKNOWN**（不编造）。
- 另有一个与 H1 同类的问题：NPC 坐标（如 `(37,85)`）与角色 `(100,42)` **相差很远**，不排除**在屏幕外**。

### 2.3 不能点击移动 —— 关键证据

```
参考服会话:  >> 10204  472 次        （客户端大量上报移动）
我的会话:    >> 10204  **0 次**      （live13/live14 命令统计里没有它）
```
⇒ 客户端**根本没有启动移动/寻路**。与"地图未初始化"（2.1）**同源的可能性最高** ⇒ **UNKNOWN**。

### 2.4 充值档位为空 —— 数据在，命令待定

- `16900` = **充值状态**（`charge:uint32, status:table`）⇒ 我现在回零值。
- 但 `analysis/1.4.9/round43_zhenbao_charge.md:69` 明确记载：**参考服当时的 `16900` 也是 `charge=0`、状态空**
  ⇒ 说明**档位内容不在这条命令里**（`16900` 只是"状态"）。
- 我手上确有真值候选：`server/mall_zhenbao.json`（**45 条**，含 `item_bid/item_name/price/limit_num/pay_type`）、
  `server/_invest_cfg.json`（投资/基金档位）⇒ **下发命令 = UNKNOWN**（下一步查哪个 `SC` 承载这些档位）。
