> 用 **3 个文件、约 1180 行**，把"**登录 → 角色 → 进场景 → 接任务 → 打怪 → 结算 → 掉落进包 → 提交 → 奖励 → 背包**"

> **0 条规格不符、0 条危险应答**。
> **真机端到端（APK 里真跑完这条回环）没做到** —— 卡点已用证据链定位在**客户端自身启动流程**（不是服务端）：

## 一、★ 已完成（逐项，附证据）

### 1.1 设计：先定"最小"的边界（这一项是本次最有价值的产出）

把回环拆成"最小命令集"，而不是把 16k 行全量服搬过来：

| 环节 | 命令 | 为什么它是"最小必要" |
|---|---|---|
| 连接 | `10001`（无 SC ⇒ 不回包）、`1199` | 不回包/回心跳，缺任何一条客户端都不会继续 |
| 帐号 | `1110` | 回 `code=1` + 角色列表；`code=0` 会走 `message(msg)` 分支弹空白框 |
| 进服 | `10102` → 推 `10200` + `10201` | **推送** 是进场景的唯一路径（客户端不发 10200） |
| 角色 | `10300` → 推 `10301/10302/10303/10304` | 四个包分别管身份/货币/属性战力 |
| 移动 | `10204` | 回发本人坐标即可（回环不需要 AOI/别人） |
| 任务 | `12400` / `12402` / `12403` | 列表 / 接取 / 提交+发奖 |
| 战斗 | `20002` → `20010` → `20012`+`20013`×N → `20020` → `20023` → `10500` | 发起/初始化/逐回合/胜负/结算/掉落进包 |
| 背包 | `10502` | 查得到掉落才算闭环 |

**结论（可被后续复用）**：这条回环**最少 11 条命令**；其余命令只要按权威 SC 出"结构正确"的应答即可，
**没有 SC 定义的命令必须不回包**（CS-only 回包会把客户端推进未知分支 —— 本项目已踩过）。

### 1.2 实现：3 个文件

| 文件 | 行数/体积 | 内容 |
|---|---|---|
| `server/minloop/min_loop_server.py` | 771 行 / 44 KB | 规格驱动编码器（读 `protocol/fields.json` 3553 条）+ SQLite 4 表 + TCP 游戏服 + HTTP 网关 |
| `server/minloop/selftest.py` | 270 行 | 离线回环自检（合成客户端 + **逐帧严格规格解析**） |
| `server/minloop/replay_real_frames.py` | 138 行 | 真机帧回放回归 |
| `server/minloop/README.md` | — | 范围、数据来源、标注纪律、诚实清单 |

设计要点（都为了"不猜"）：
- **字段顺序/宽度/嵌套表结构全部从 `fields.json` 读**，一个字都不手写 ⇒ 从根上避开本项目"SC 被截断 4 次 / 字段宽度错 6 次"那类 bug。
- 通用路径：任何有 SC 的命令都能出**结构正确**的应答（内容零值/空表，**不假装有数据**）。
- 独立端口与独立 DB（`--http 8099 --game 9099`、`server/minloop/minloop.db`）⇒ **绝不碰**参考服的 8080/9000 与 `state/roles.db`。

### 1.3 离线自检：**44/44 PASS**（可复跑）

```
python server/minloop/selftest.py      →  检查项 44，通过 44，失败 0
```
覆盖并**逐帧严格解析**（少字节/多字节/结构不符 ⇒ 直接 FAIL）：
10001 不回包 → 1199 → 1110(`code=1`, 角色列表≥1) → 10102 + 推 10200(bid>0) + 10201(roles=1, mons≥1)
→ 10301/10302/10303/10304 → 12400(链头) → 12402(接取 code=1) → 20002 完整战斗链 → 12403(提交+发奖)
→ 10502(背包) → 回环外命令走通用应答。

实测到的回环**业务结果**（不是"结构对"而已）：
```
<< 20013 回合1 伤害 -790 → 怪HP 1610/2400
<< 20013 回合2 伤害 -790 → 怪HP  820/2400
<< 20013 回合3 伤害 -790 → 怪HP   30/2400
<< 20020 战斗结果=胜
<< 10500 掉落进包 bid=33001          ← 库里真多了一件（before=0 after=1）
** 任务 10010 奖励 {'coin': 1290, 'exp': 500, 'hero_exp': 500}   ← 与 APK 里 award_assets=[[2,1290],[4,500],[15,500]] 一致
<< 10502 背包 items=1                ← 提交后背包查得到
```

### 1.4 ★ 真机帧回放：**8831 帧 / 184 命令 / 规格不符 0**

拿 **MuMu 里那台真机 APK 实际发出的字节**（服务端抓包日志的十六进制转储）回放给最小回环服：

```
python server/minloop/replay_real_frames.py logs/1.4.9/battle_chain_tcp.log \
       logs/1.4.9/task_chain_tcp.log server/logs/tcp_prevR.log
→ 服务端应答覆盖命令 184 条，应答帧合计 8831
→ 回环命令在真实流量里出现过并被正确应答：1110,1199,10102,10204,10502,12400,12403,20002
→ 规格不符（多/少字节）：0
→ 危险应答（code=0 且 msg 空 / 非法 code）：0
→ 诚实拒绝（code=0 且有 msg）：44（"未接取"×42、"怪物不在场"×2）
```
44 条拒绝**不是 bug**：回放是"无上下文乱序"的（真机的提交帧落在本服没接过的任务上、真机的怪 id 不在本服场景里），
按本项目纪律"操作型未满足 ⇒ 明确回 `code=0` + msg"，这正是**该有的诚实拒绝**。

### 2.1 ★ 真机端到端的**证据链**（5 条，逐条可复查）

| # | 观察 | 证据 |
|---|---|---|
| 1 | 已知可用 APK 冷启动后**自己不发连接** | `server/logs/tcp.log` 在 22:39:43 启动后无任何新增连接行 |
| 2 | 探针强制建连能成功（要**周期重试**，调一次不够） | 22:12 只调一次 ⇒ 无连接；22:23/22:30/22:32/22:51 周期重试 ⇒ 每次都有连接 |
| 3 | 连上后**发送路径被走到但抛异常** | 探针 v3 追踪：`ml3_send_pre=BaseController_type=table(m_type=cs,m_msg_type=10001,key=game_client)` 之后**没有** `send_post` ⇒ `SendProtocal` 内部抛错 |
| 4 | 客户端登录路径运行在**未初始化**状态 | 探针 v3：`OnNetAsyncConnected` 报错 `game/login/denglu_ctrl.luac: attempt to index global 'SceneEvent' (a nil value)` |
| 5 | 每帧的**网络泵**也抛异常 | 探针 v4：`ml4_pump=ok=false`（`GameNet:Update()` 直接失败）⇒ socket 连着也没人收发 |
| 6 | 客户端**画面 40 分钟逐像素不变** | `logs/minloop/ref_01_after_launch.png`（22:12）与 `logs/minloop/live_real_apk_screen.png`（22:53）**平均像素差 0.00/255** |
| 7 | 探针 tick 在启动后约 40 秒停摆 | `DSH_PROBE?t=state&v=t_1185...` 之后不再有 tick 上报 |

**⇒ 结论（CONFIRMED）**：客户端启动流程在当前环境下**走不完**（tick 停摆、登录全局未定义、网络泵抛异常），
因此**服务端做对了也收不到帧**。这不是最小回环服的缺陷 —— 同一时间窗里，服务端侧一切正常（HTTP 200、TCP 已建立、回放 8831 帧零缺陷）。
**唯一一次历史上跑通整条链**（21:28:50 的 `10001→1110→10102→10200/10201`）来自更早那次长时驻留的会话状态。

## 三、该怎么优化（按性价比排序）

| # | 优化项 | 具体动作 | 预期收益 |
|---|---|---|---|
| 1 | **让客户端"能动"** | 定位 tick 停摆点：在 `main.luac` 的 `initSchedule()` / `restartNetManager` 前后各埋一个落盘上报，判定是"调用阻塞"还是"调度被重置"。本项目文档已指出 `GameNet.doOneMsg` 是**不受调度重置影响**的每帧钩子，可作为驱动的可靠挂点 | 一旦能动，真机端到端立刻可验 |
| 2 | **绕开登录 UI** | 不依赖客户端自己的登录流程：探针在连上后**自己调 `SendProtocal`**（用 `GetPrototype(cmd)` 构造 proto），把 `10001/1110/10102` 发出去。本次已确认发送器会被走到，只差把 proto 对象构造对 | 直接打通真机回环 |
| 3 | **视觉能力** | 本模型**不能读图**（`read_image` 报不支持），本次只能靠"探针文本上报 + 像素差 + 服务端日志"判断客户端状态。若后续要按屏幕点按钮，需要一个能读图的模型或额外 OCR | 恢复"点任务条→自动寻路"这类 UI 驱动 |
| 4 | 战斗手感 | 伤害系数 `DAMAGE_SCALE` 现标定到"3 回合打完 2400 血"（参考服实测 ~772/击、~3 回合） | 手感接近参考服 |
| 5 | 最小回环的**性能** | 现在是"一请求一应答同步推"，没有 tick/批量；参考服有 200 并发基准（中位 10.8–16.9ms） | 多连接时更稳 |
| 6 | 把最小回环当**回归门禁** | 它 3 个文件跑 20 秒就能验完一条回环 ⇒ 可以进 CI，比 66 项回归更轻 | 改参考服后先跑它 |

## 四、该怎么继续复原玩法（路线）

1. **先解"客户端能动"这一个点**（§3.1/3.2）—— 它是**唯一**挡住真机验证的墙，且已缩到很小：
   - 已知：连得上、发送器会被走到、报错在 `SceneEvent` nil 与 `GameNet:Update` 抛异常。
   - 下一步：把驱动挂到 `GameNet.doOneMsg`（每帧、不受调度重置），并在 `SendProtocal` 外面抓真实异常栈（v3 已留钩子，只是当时把错误吞了）。
2. **真机跑通最小回环后**，按"最小 → 参考服"的顺序补：
   1) `10201` 的真实 NPC/怪摆位（本项目已有 19 个真实 NPC 坐标，最小回环已接）
   2) `15203` NPC 对话 → 剧情接取（让"点 NPC 接任务"这条原版交互成立）
   3) 自动寻路（`missionGoto` 的真实 `mis_code`，本项目列为待抓）
   4) 掉落表 / 怪物数值 —— **只能占位**（APK 无数据，取证天花板）
3. **横向系统**（公会/拍卖/结婚/跨服/副本/社交）：工程量数倍于现有，优先级最低；
   照最小回环的做法，**每条系统先做"最小可验证子集"**，别一上来铺全量。
