## 二、★ 本轮又发现并修掉一个**自己新代码**里的真 bug（值得记录）

| 项 | 内容 |
|---|---|
| 现象 | 首跑 `12415` **完全没有应答**（`code=?`），3 条断言失败 |
| 定位 | 自检输出里有 `!! 回环处理 12415 异常` + `AttributeError: 'sqlite3.Row' object has no attribute 'get'` |
| 根因 | 我在新写的 `bag_has()` 里写了 `(r or {}).get('n')`，但本服 `Store.one()` 返回的是 **`sqlite3.Row`**（不是 dict） |
| 修复 | 改为 `int(r['n']) if r else 0` ⇒ **132/132** |

**教训（与 round 16 的 `import re` 同源）**：
**新增的辅助函数若不被断言覆盖，其异常会被服务端 per-message 的 `except` 静默吞掉**，
表现就是"客户端收不到任何应答"（而不是一个明显的报错）。
⇒ 本轮之所以能很快定位，正是因为**先给新命令写了断言**（否则会变成"悄悄不工作"）。
