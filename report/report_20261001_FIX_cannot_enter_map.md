# 「无法进图」修复报告 —— 根因：`10103`（角色重连）未实现，**不推场景数据**

> 时间：2026-10-01 ｜ 目标 APK `anzbao/jstm.apk` 1.4.9 ｜ 验证：**真机实测通过**

---

## 〇、结论

> **无法进图的根因找到了，并已修复、真机验证通过。**
> 根因：**`10103`（角色重连）没有专用处理** —— 它落到"通用应答"分支，
> 只回一个结构零值的 `code=1`，**完全不推 `10200`（进场景）与 `10201`（场景格子）**。
> 而客户端**重连时走的正是 `10103`**：它会 fire `LOGIN_SUCCESS` 去进场景，**却没有任何场景数据可建** ⇒ 卡在进图。
>
> 依据（参考服实机注释 + 反汇编出处）：`10102` 与 `10103` 的 SC **结构相同**，
> 两者的处理器都写 `if resp.code == TRUE then … SendProtocal(10300); LoginSucceedSendProtocal();
> DengluEvent:Fire(LOGIN_SUCCESS)`，而 `scene_controller` 把 `LOGIN_SUCCESS` **绑到进入场景**。

## 二、修复内容（`server/minloop/min_loop_server.py`）

```python
def on_10102(self, body, cmd=10102):     # ← 参数化，同时服务 10102 与 10103
    cs = self.spec.read_cs(cmd, body)    # ← 按实际命令解 CS
    ...（角色确保逻辑不变）
    self.send(cmd, values={'code': 1, ...})   # ← 按实际命令回 SC（10103 就回 10103）
    self.push_10200()                    # ★ 进场景
    self.push_10201()                    # ★ 场景格子

def on_10103(self, body):
    return self.on_10102(body, cmd=10103)
```
并把 `10103: 'on_10103'` 注册进 `LOOP`。
