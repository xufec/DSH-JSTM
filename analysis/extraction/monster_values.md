## 2. 怪物配置表诊断

### 2.1 config_mon_data.luac (1.4.11)

- **文件**：`_tmp_cfg/config_mon_data.luac`，857,309 字节
- **反构造结果**：`server/cfg/config_mon_data.json` 仅 311 字节，Mon / MonData 主表均为空 `{}`
- **反汇编证据**：`analysis/1.4.9/task/_mon_dis.txt` 显示 luac 内含 13,267 个 TableConst（怪物定义数组）+ 7,956 个数字常量（怪物 ID）
- **失败原因**：标准反构造脚本（config_deconstruct.py）无法处理该 luac 的嵌套结构——它用 `TDUP + TNEW + TSETS` 组合构建怪物表，但脚本的顶层键提取逻辑未匹配此模式
- **结论**：数据在 luac 里是存在的，只是反构造脚本没解出来。但即便解出来，根据 1.4.9 对照可知**怪物表里没有显式战斗数值**

### 2.4 关键结论：怪物表无显式战斗数值

- **HP**：无（不同等级怪物的 field[14] 都是 170，证明不是 HP）
- **ATK**：无
- **DEF**：无
- **EXP**：无
- **Coin**：无

**怪物 HP/ATK/DEF/EXP 均由服务端公式计算**：
```
实际数值 = 等级基础值(level) × 类型倍率(type[3]) × 缩放系数(scale[21])
```

公式本身在服务端战斗模块（mock_server.py battle.py / power.py）中，不在配置表里。

## 8. 对 mock_server 的影响

- mon 20001: HP=2400, coin=+30, dmg=784

**配置表无法提供这些数值的真值。** 替换路径：
1. **短期**：基于 1.4.9 怪物等级分布 + field[21] 缩放系数，用经验公式估算合理数值（标记 INFERENCE）
2. **中期**：反编译服务端战斗模块（battle.py / power.py）提取公式
3. **长期**：MuMu 模拟器运行 1.4.11 客户端 + mock_server，实机打木桩采集真实数值
