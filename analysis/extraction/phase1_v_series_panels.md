## 一、⚠ 操作事故：我的探针脚本**盲发 BACK 把游戏退出了**（必须记录）

### 1.1 事实

前几轮的 UI 探针脚本在每个坐标点后固定发 2 次 `input keyevent 4`（BACK，意图"关面板"）。
实测：**在世界界面按一次 BACK 关面板没问题，按第二次 BACK 会直接退出游戏到 Android 桌面**。

```
topResumedActivity = app.lawnchair/.LawnchairLauncher     ← 游戏已被退出
（此前为 com.shiyue.dldl.ewan.baidu2/org.cocos2dx.lua.AppActivity）
```

时间线证据：`server/logs/tcp.log` 在 **13:44:54 → 20:15:57 之间完全静默**（6.5 小时无任何 CS），
而第 4、5 轮的部分 UI 点击实际上打在**已退出的桌面**上。

### 1.2 影响评估（诚实版）

| 轮次 | 产出 | 是否受影响 |
|---|---|---|
| 第 4 轮（316 命令解码 / bid 覆盖度）| 全部来自 **13:00–13:44 的抓包文件** | ❌ 不受影响 |
| 第 5 轮（战斗 SC 解码 / 服务端参照值）| 全部来自 **服务端只读端点** | ❌ 不受影响 |
| 第 4–5 轮的 UI 点击（若有）| 打在桌面 | ✅ 无效（但当时结论未依赖它）|

### 1.3 恢复（已验证）

```powershell
adb shell am start -n com.shiyue.dldl.ewan.baidu2/org.cocos2dx.lua.AppActivity
```
45 秒后客户端**自动登录并重连**（服务端重启/客户端冷启均会自动重连）：

```
[20:15:57] >> cmd=10502 body(5)=08 00 00 00 13      ← 背包同步
[20:16:01] >> cmd=10204 body(8)=00 7e 00 31 13 8f 00 00   ← 移动 (126,49)
[20:16:02] >> cmd=1199 心跳 body(4)=00 7e 00 31
/status: pos=(126,49) scene=10001 lv=70  ⇒ 运行态恢复 CONFIRMED
```

> 附带又验一次残留机制：心跳 4 字节 `00 7e 00 31` = (126,49) = **上一帧 10204 的开头**，与 R-7 一致。
> **纪律（写给下一个 agent）**：探针脚本**禁止盲发 BACK**；每次操作前后查
> `dumpsys activity activities | grep topResumedActivity`；需要关面板时用面板自己的 X。

## 二、★ SC 证据源分级修正（本轮最重要的方法学更新）

前几轮我写过"SC 侧无抓包 ⇒ 只能 STRONG_INFERENCE"。复查后修正为**三档来源**：

| 档 | 来源 | 覆盖 | 等级 |
|---|---|---|---|
| **A. SC 原始字节** | `GET /DSH_ADMIN/battle_replay`（服务端构造的 hex） | **仅战斗族**（20002/20010/20012/20013/20020/20023） | **CONFIRMED**（能按规格逐字段解出）|
| **B. SC 字段值注释** | `server/logs/tcp.log` 的 `<<` 行（服务端自己打印关键字段） | 655 行中 **253 行**带 `=` 值 | **CONFIRMED（服务端实现）**；⚠ 是"服务端声称发了什么"，**不等于客户端正确渲染** |
| **C. SC 规格定义** | `protocol/fields.json`（1.4.9 `cmd_resolve` 反汇编） | 3,553 条 | CONFIRMED（结构）／值需 A 或 B |

**B 档的价值**：它让"服务端下发了什么"从猜测变成可查，例如本轮读到的：

```

<< 12901 SC_12901 排行榜 val=724112 (119 bytes)
<< 12971 SC_12971 type=301 rid=1001 战力=724112（分项未取证=0）

<< 10534 SC_10534 val=0（无数据源，如实回 0）
```

### V-4 日常面板：**服务端发了值，客户端显示 `????/????`**（新增真问题）

实机截图 `shots/v_daily2_201708.png`：面板标题 `日常`，页签 `日常活动 / 限时活动`，
行内容 `拥有活力: ????/????`、`生产技能`、`每日凌晨5点刷新`、`双倍点数 0`、`50级礼包` `领取`。

而服务端**确实下发了**：`total_val=10`、`huoli_list=12`、`lingqu=0`。

⇒ **判定：服务端 SC 值 ≠ 客户端渲染值**（UI 出现 `????`，即数值未成功格式化/取值）。
可能原因（**INFERENCE**，待证）：① `13781` 的 SC 结构与客户端期望不一致（字段错位/类型不符）；
② 客户端读的是另一帧；③ 需要额外初始化帧。**这是 D2 渲染类问题的同族，值得单独立项。**

### V-5 称号：三方自洽（可作为"回空=真话"的正例）

| 来源 | 值 |
|---|---|
| 服务端 SC 注释 | `<< 14901 cur_bid=0 titles=0（role_title 真值）` |
| 服务端端点 | `/DSH_ADMIN/title` → `titles: []` |
| 数据库 | `role_title` 表 0 行 |

⇒ **服务端三处自洽为"空"**；客户端若显示空列表 → 正确；若显示异常 → 客户端问题。
（本轮未截到称号面板 UI，标"待取证"。）
