### 4.2 ★★ 终局证据：`code` 语义（反汇编 `action_ctrl.luac` proto#7）

客户端处理 `SC_16605` 的逻辑（`game/action/action_ctrl.luac`，proto#7，`knum=[1]`）：

```lua
-- KPRI 0=nil / 1=false / 2=true
function(self, target_bid)
  local v2 = false                                  -- KPRI A=2 D=1 ⇒ 默认 false
  if not self.act_state_list then return v2 end
  if not self.act_state_list.status then return v2 end
  for _, v in ipairs(self.act_state_list.status) do
    if v.bid == target_bid then
      if v.code == 0 then v2 = false                -- code == 0 ⇒ 未开启
      else                v2 = true                 -- code ~= 0 ⇒ **开启**
      end
      break
    end
  end
  return v2                                          -- **找不到 ⇒ false（未开启）**
end
```

（proto#8 是同一逻辑的"取该 bid 的状态条目"变体，`MOV A=2 D=8` ⇒ 返回条目本身。）

**⇒ 结论（CONFIRMED）**：
1. **`code != 0` = 开启；`code == 0` = 未开启；列表里没有该 bid = 未开启。**
2. **回空表 ≡ 全部未开启** —— 这就是旧实现导致「活动入口/图标不显示」的**直接原因**。
3. 要"开启"**必须为每个 bid 显式回一条 `code != 0` 的记录**。

### 4.3 落地实现（PHASE 2.18）

`mock_server.py` 的 `16605` 分支改为：按请求的 `bid_list` **逐条回 `{bid, code=1, end_time=0}`**

[17:20:40] << 16605 SC_16605 status=108 code=1（客户端语义：code!=0=开启）

### 6.3 ★★ 已解：`act_list.id` 的身份与客户端门槛（proto#30 实测）

`Activityhander10925`（proto#30）开头就是这段（**逐指令读出，CONFIRMED**）：

```lua
local rv = GameData:getInstance():getRoleVo()
if rv == nil then return end
local lev = rv.lev
self:setActiData(data.id, data.status, data.int_args)
self:showCommonAlert(...)

local fn = Config.Function[data.id]          -- ★★ 用条目的 id 去查 **config_function**
if fn == nil then return end                 --    查不到 ⇒ 不处理
if fn.is_open ~= 1 then return end           -- ★ is_open != 1 ⇒ 不处理
if lev < fn.open_lev then                    -- ★ 等级不足
    self:pushUnopenList(data.id)             --    ⇒ 计入"未开启"列表
    return
end
-- 否则按 data.id 分派到具体活动控制器
```

**⇒ 决定性结论（CONFIRMED）**：
1. **`act_list` 条目的 `id`(u16) 就是 `config_function` 的键**（`Config.Function[data.id]`）。
2. 客户端自带的门槛是 **`is_open == 1` 且 `open_lev <= 角色等级`**；
   不满足的会被丢进 `pushUnopenList`（"未开启"）⇒ 这正是活动图标不显示的判定处。
3. 因此实现 `10924` 时，**只应下发 `is_open==1 && open_lev<=lev` 的 id**；
   下发别的会被客户端丢进"未开启"。

**已核**：`config_function` 的 91 个键 =
`3,5,6,8…34,37,40,41,43,44,47,48,51,52,56,62,101,102,103,106,107,110,113,114,115,117,121,501..506,
1000,1002,1008..1014,2000,3000,4000,5000,6000,7000,9000,10000..29000`（皆 ≤ 65535 ⇒ 与 `id:u16` 相容 ✓）。

> ⚠ **`16605` 的 108 个 bid 与 `config_function` 键无交集**（已逐项核）⇒ `16605` 与 `10924`
> 用的**不是同一套 id 空间**，两者不可互推。`16605` 的来源仍待定。
