## 一、★ 修掉上一轮的功能性缺口：`30502` 在游戏内**永远领不到**

**问题**：PHASE 2.13 实现了 `30502 领取充值奖励`，门槛是
`total_charge >= GrowthTarget[day].charge_gold`。但当时**没有任何链路写入 `total_charge`**
（只暴露了 `service.set_total_charge()`）⇒ **游戏内 `30502` 恒返回「累计充值不足」**。
这是我上一轮留下的真实缺口，本轮修。

**取证（真实流量）**：

| cmd | 名称 | 客户端发 |
|---|---|---|
| `13901` | 充值查询 | **2** |
| `13902` | 充值 | **0**（私服里充值只能经 GM 发放，客户端不会真的充值）|
| **`16900`** | **累积充值可领取状态** | **3** |
| `16901` | 领取累积充值奖励 | 0 |

⇒ 客户端真正会看的"累计充值"入口是 **`16900`**。

**改动**：`mock_server.py` 的 `16900` 分支，`charge` 从**硬编码 0** 改为
读 **`growth_target.service.state(rid)['total_charge']`** —— 与 `30502` 的**门槛同一数据源**，
消除"面板 0 / 后端另一套值"的双口径。`status` 仍回**空表**（各档 `key`/`state` 语义未取证 ⇒ 不编造）。

**验证**（实测）：
```

16900 回包 body = 00 00 00 50 00 00   ⇒ charge = 0x50 = 80 ✓（status 计数 0）
清库后 role_gt = 0
```

## 五、★ 补完（PHASE 2.16b）：GM 累计充值**写**入口

⇒ 游戏内 `total_charge` 恒 0 ⇒ `30502 领取充值奖励` **永远领不到**
（`13902 充值` 客户端发=0，私服里充值只能经 GM）。这是"接了一半"的典型。

**改动**（`mock_server.py` `do_GET` 的 `/DSH_ADMIN/*` 路由内，紧随 `setlevel` 一族）：

```
GET /DSH_ADMIN/setcharge?n=80[&rid=1001]
  → growth_target.service.set_total_charge(rid, 80)   ← 走正式 Service，**不直改 DB**
  → {"ok": true, "rid": 1001, "total_charge": 80}
```

**验证（端到端实测）**：

⇒ **充值奖励链路现已游戏内可达**：
