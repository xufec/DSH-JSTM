# 第二十轮：路线 1 取证 —— 属性向量是多源计算的，非单表

> 用户指定走"彻底逆 CalAttr"的路线 1。本轮做了系统取证，**结论与计划**如下。

---

## 一、本轮确证的几个事实（CONFIRMED）

### 1. 找不到"每级属性成长表"

| 已排查的表 | 内容 | 结论 |
|---|---|---|
| `config_role_attr` | `exp_total/exp_max/sinew_max/attr_point` | 等级**经验/体力**表，**无 atk_s 等** |
| `config_role_cost` | `{sinew:50,100,100...}`（100 条） | **体力消耗**，非属性成长 |
| `config_role_career` | 6 职业，`attr` 字段是 **TNEW 空表** | 职业基础属性不在配置表给死 |
| `config_attr` | 64 项属性**定义 + 战力权重** | ✓ 已完整提取到 `_attr_data.json` |

### 2. 属性向量的存储模型已定位

```
game/role/role_vo.luac  proto[0]   ← 角色属性存储（含 atk_s/hp_max 等键）
game/hero/vo/hero_vo.luac          ← 伙伴属性存储
```

但**这些是"存值"的 VO，不是"算值"的函数** —— 真正的计算在别处。

### 3. ★ 决定性结论：属性向量是**多源计算**的

```
角色属性 =
    职业基础(attr，TNEW 空 → 需程序填充)
  + 等级成长(无单表 → 客户端公式计算)
  + 装备(equip)
  + 属性点(attr_point，手动分配)
  + 时装/魂骨/魂环/伙伴羁绊... (misc)
```

**⇒ 这是一整套属性系统，不是一张表或一个公式能概括的。**
