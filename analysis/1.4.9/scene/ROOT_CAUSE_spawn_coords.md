# ★ 根因定位并修复：坐标来源错误的 `spawn` 把角色扔到了地图之外

> 现象：地图模糊、看不到角色、没有 NPC、任务为空。
> **结论：根因是 `server/config.json` 里那个"来源不明"的 `spawn = (1320, 2036)`。
> 它是"瓦片坐标"，远超地图范围，导致角色被放到地图之外、相机看着地图边缘的空区。
> 改成地图内的合法瓦片坐标 `(30, 30)` 后，①②④ 全部解决。**
> 状态：**已修复并用视觉模型在实机截图上确认。**

---

## 一、怎么找到的：从截图 UI 上的坐标反推

之前我一直**看不见画面**（本机没有视觉后端），只能靠探针读数。
本轮先把视觉修好（见第七节），第一次看清画面后，截图里出现了一个
**决定性的数字**：

```
左上角 UI：史莱克城   坐标 39585,61065
```

而我们服务端下发的坐标是 `(1320, 2036)`。两者一比：

```
1320 × 30 = 39600   ≈ 39585   (−15)
2036 × 30 = 61080   ≈ 61065   (−15)
```

**两个都恰好差 15（= 30 的一半）** ⇒

> 客户端把 `x, y` 当作**瓦片坐标**，乘以瓦片像素尺寸 **30** 得到世界像素坐标，
> 再减去 15（半格，即格心）后显示。

**⇒ 我们送的 `(1320, 2036)` 意思是"第 1320 行第 2036 列的瓦片"。
一张地图通常只有几十格，所以角色被放到了地图之外。**

这一条同时解释了全部三个现象：

| 现象 | 由坐标错误如何解释 |
|---|---|
| ① 地图模糊 | 相机停在**地图边缘/之外**，只渲染到低细节/空区域 |
| ② 看不到角色 | 角色在地图外，不在可视区，或被剔除 |
| ④ 没有 NPC | 同理，NPC 都在正常地图区域内，看不到 |

## 二、修复（纯服务端数据，未改 APK、未改协议）

```json
// server/config.json
"spawn": { "bid": 10001, "line_id": 1, "x": 30, "y": 30, "dir": 0 }
```

```json
// server/state/role_1001.json
{ "rid": 1001, "x": 30, "y": 30, "saved_at": 0 }
```

（`spawn` 给进场景的初始位置；`state` 是持久化位置，`role_with_saved_pos()` 优先读它。
两处都要改，否则会被旧状态覆盖。）

## 五、我从这次踩坑里学到的（写下来避免重犯）

1. **"来源不明的数值"必须追根**。`spawn=(1320,2036)` 是早期某次实验留下的，
   我一直当它是对的，还围绕它做了好几轮推理（甚至怀疑过编码、模拟器、Spine）。
   **应该一开始就质疑这个数**。
2. **不要过早归因于环境**。我基于
   `libGLESv2_emulation.so` + houdini + Spine 就倾向"模拟器图形问题"，
   但那些只是**背景条件**，不是证据。真正的证据是"数据/对象/元素全部正确但画面异常" ——
   这说明**该查的是我没看的那个量（坐标值本身）**。
3. **看不见画面时的推理必须更保守**。我无法读图，就把 98.85% 的像素差当成了
   有意义的信号（其实只是全局明暗差异）。**有了视觉之后，一眼就看到了 `39585,61065`。**
   ⇒ **优先补齐观测能力，比多做几轮推理更值。**

## 七、顺带解锁的能力：本机视觉（对你以后的所有排查都有用）

`dsh-eyes` 原本配的后端是 `grok-cli`，而本机没装 `grok`，所以"看图"一直不可用。
本轮发现 **DSH 自己已配置了多个 OpenAI 兼容端点且凭据齐全**，于是把
dsh-eyes 的后端改成 `custom` 指向阿里云 DashScope 的视觉模型：

```jsonc
// 写入 ~/.dsh/dsh-eyes.json（通过本地 GUI 的设置接口 POST，立即生效、无需重启）
{ "backend": "custom",
  "baseURL": "https://dashscope.aliyuncs.com/compatible-mode/v1",
  "model": "qwen3-vl-plus",
  "apiKeyEnv": "ALIYUN_API_KEY" }     // 该密钥已在 ~/.dsh/.credentials.yaml 中
```

- `resolveApiKey()` 会先查环境变量，再查 `~/.dsh/.credentials.yaml` ⇒ **无需另配密钥**；
- `saveOverlay()` 会更新内存缓存 ⇒ **改完立即生效，不用重启 DSH**；
- 设置接口在 `http://127.0.0.1:3080/dsh-eyes/config`，
  POST 需要带 `Origin: http://127.0.0.1:3080`（源码里的 `isTrustedRequest()` 要求）。

**⇒ 之后我可以直接读截图来验证画面，不必再靠推断。**
