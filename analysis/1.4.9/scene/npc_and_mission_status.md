## 二、NPC（历史记录，供追溯）

### 2.1 已确认的事实

**视觉模型对当前画面的判读**（`shots/stage3_now.png`，修复坐标后）：

> "除玩家主角（DSH，蓝甲持剑，位于画面中央偏左石板路）外，**无其他可见人物、NPC 或怪物**；

> "**无任何 NPC 头顶名字或感叹号/问号标记**。"

⇒ **场景里确实一个 NPC 实体都没有**（不是"没渲染好"，是"没有"）。

### 1.2 根因方向（有依据）

`scene_controller.on10201`（proto[9]）的字符串显示它做的是：

```
roles → addRole     npcs → addNpc     mons → addMonster     elems → addElement
```

而我们的 `10201` 里 **`npcs` 一直是 0 项**：

```
t=on10201&v=roles_1_npcs_0_mons_0_elems_0
```

⇒ **没有数据可加，自然没有 NPC。**

### 1.3 本轮已做

1. 从客户端配置 **`assets/src/config/config_map_npc.luac`** 提取到真实数据线索：
   每张地图的 NPC id 列表（如 `[10001]`、`[10001,10005]`），
   以及 `MapSceneDoors` 条目（形如 `[20007,52,27]`、`[20006,45,30]` → id + 坐标）。
2. 在 `mock_server.py` 新增 `build_npcs()`，并让 `build_10201(roles, npcs)` 支持 npcs；
   两处 `10201` 下发（应答 + 进场景推送）都带上 `config.json` 的 `npcs`。
3. `config.json` 加了 3 条 NPC（用上面提到的真实 id/坐标：
   `20006@(45,30)`、`20007@(52,27)`、`20008@(15,56)`）。

**编码约定**（沿用**在 roles 上已被证实可用**的那套，不是纯猜）：

```
id:u32, bid:u32, type:u8, x:u16, y:u16, name:string,
misc         → u16 0          (Dsc10201misc，提取器标注"无字段")
animate_res  → u16 0
member       → u16 0
```

## 二、任务栏

### 2.1 已确认的事实

从修复后那一轮的 TCP 日志对比"客户端发出"与"服务端回复"，**未被回复的命令**有：

```
10001 10300 10800 10923 11300 11301 13200 13300
15801 16601 16605 18803 19400 19406 30715
```

其中相当一部分在 `proto_defs` 里**只有 `SC_*` 定义、没有 `CS_*`**
（`10800 / 11300 / 11301 / 13200 / 13300 / 15801 / 18803 / 19406`）
⇒ 这些按设计是**服务端主动推送**的通知，而不是"客户端来请求、服务端应答"。

**推论（未验证）**：任务列表很可能**也属于"服务端主动下发"那一类**，
即客户端不会主动请求，我们必须**主动把任务数据推给客户端**，任务栏才会显示。
