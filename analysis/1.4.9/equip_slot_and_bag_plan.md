# 第 1 步：装备槽位不匹配 —— ✅ **已修复**

## 1.1 取证一：槽位由**服务端回包**决定（客户端字节码）

`backpack_ctrl.luac` → `handle_10511`（proto[34]）：

```lua
@14 'rolePutOnEquip' / @18 CALL
@19 resp.eqm_new_pos      ← ★★ 槽位用的是**响应里的** eqm_new_pos
```

**⇒ 我原实现把 `eqm_new_pos` 硬编码为 **0** ⇒ 所有装备落到同一格 ⇒ 冲突。**

## 1.2 取证二：**部位就是物品的 `type`**（客户端字节码）

`common/shortcut_equip_panel.luac` proto[4]：

```lua
@22 GGET 'Config' / TGETS 'Item' / TGETS 'bid' / TGETV   → Config.Item[bid]
@26 TGETS 'type'              ← ★★ 物品的 type 就是客户端的 `equip_type`
@30 TGETS 'equip_type' / @31 ISEQV
```

## 1.3 ★ 关键发现：**旧的物品表提取是错的**

| | 旧表 | **新表** |
|---|---|---|
| 文件 | `analysis/1.4.9/item/config_item.json` | **`server/item_config.json`** |
| 条数 | **1117** | **3535**（旧的少了 2/3） |
| 装备类 | **错位**（`41601`→'2星转灵神丸'、`41001`→'5'） | **正确** |
| 提取方式 | 位置下标（猜测） | **字段顺序从字节码逐条读出** |

**新提取器 `tools/extract_item_v2.py`**：字段顺序 **不是猜的** ——
从 `config_item.luac proto[0]` 的 `TGETB`+`TSETS` 配对**动态推出**：

```
[bid, name, type, lev, bind_type, quality, grade, overlap, durable, use_type, ...]
```

**⇒ 修正后（实测）：**
```
40001 type=100 '见习长枪'      41001 type=106 '见习护手'
41801 type=103 '见习腰带'      41211 type=107 '见习布靴'
41401 type=104 '见习草帽'      33001 type=6   'VIP2每日礼包'  ← 礼包
41601 type=105 '见习灵袍'
```

## 1.4 ★ 权威「部位 → 槽位」映射（逐类核对名称得出）

```json
"equip_type_slot": {
  "100": 1,   // 武器（63 件：见习/玄铁/黄金/秘银长枪）

**未命中的 type（如 `6` 礼包，897 件）一律**拒绝穿戴**。

## 1.5 实测（独立 TCP）

```

② 按部位穿（每部位落到各自固定槽）：
   40003 type=100 → eqm_new_pos=1  秘银长枪
   41803 type=103 → eqm_new_pos=2  流光腰带
   41403 type=104 → eqm_new_pos=3  流光皮帽

**⇒「武器被礼包占了位」彻底解决：礼包被拒绝 + 武器固定在槽 1。**
