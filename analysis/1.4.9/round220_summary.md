## 五、★★★ 61 条纪律（**本会话新增 25 条：37–61**）

| 条 | 要点 |
|---|---|
| 37 | "计数"要从**正确的层级**取（`len(kgc)` 而非"最大列表长度"）|
| 38 | **"读 DB 的接口"要先 grep**，不要猜 |
| 39 | **"配置源"的假设必须验证**，不能凭名字 |
| 40 | **配置/表的"行形态"有两种**（一 dict 装 N 行 / N dict 各装一行）|
| 41 | **"字段名对应" ≠ "数值可得"** |
| 42 | **"自动匹配配置源"是陷阱**（通用词污染）|
| 43 | **清单清零后，"批量推进"失去对象** |
| 44 | **"自动化挂钩"必须报告"是否真生效"** |
| 45 | **"DB 可填"要"逐名对应 + 空则不填"** |
| 46 | **"字段名重合"在"字段被多处复用"时会失效**（**要加语义层**）|
| 47 | **"配置源存在"必须再验证"键/对应关系"** |
| 48 | **`elif`/`if` 链中间不能插独立语句** |
| 49 | **"死代码/遮蔽"判据必须覆盖所有分发形式**（**含 `cmd // K == N`**）|
| 50 | **"服务端推送型"命令没有"请求分支"** |
| 51 | **"新增工具前先 grep 现有实现"** |
| 52 | **"未实现清单"必须区分 `CS+SC` 与"只有 SC"** |
| 53 | **"静态查源码"的正则必须覆盖"单行写法"** |
| 54 | ★ **"接上数据源"必须做"端到端证明"** |
| 55 | ★ **"改进行为"时必须同步更新"断言旧行为的回归"** |
| 56 | ★ **端到端证明要做"双向"**（`before≠mid` **且** `after==before`）|
| 57 | **日志里的"数值"必须从"实际编码的变量"取，不能写死** |
| 58 | **"检查日志"必须"运行时抓"，不能"静态扫源码"** |
| 59 | **"补完一条命令"应先找"已实现的同构命令"** |
| 60 | **"同源子表"扫描要按"重合数排序"** |
| 61 | ★ **判"是不是子表"要用 `type == 'table'`，不能用 `items` 非空** |
