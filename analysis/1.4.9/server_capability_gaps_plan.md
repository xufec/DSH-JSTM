## ② NPC 交互（对话）没了 —— ⚠️ **根因已定位，修复待做**

### 根因（字节码确证，来自前几轮调查）

```
npc_dialogs proto[8] (openDefault) 开头：
   @0 TGETS 'ctrl'  @2 TGETS 'setOpenNpc'  @4 CALL      ← self.ctrl:setOpenNpc(...)
npc_ctrl proto[84]  是**类定义块**：GGET NpcCtrl + FNEW + TSETS '方法名'（setOpenNpc 在内）
```

**⇒ 实测枚举 `NpcCtrl` 实例只有 `New/__delete/__init/super`，**没有 `setOpenNpc`**
⇒ **`npc_ctrl proto[84]` 的类定义块没有执行**（其开头是 `GGET NpcCtrl / IST / JMP` 的**懒加载守卫**）
⇒ `openDefault` 调用时炸：`attempt to call method 'setOpenNpc' (a nil value)`。**

### 方案（分两步，先验证再改）

1. **验证**：包住 `npc_ctrl` 的类定义入口，观察 `proto[84]` 何时执行、`NpcCtrl` 上何时出现 `setOpenNpc`
2. **修复**：确保调用 `openDefault` 之前类定义已完成
   （或在探针里把 `NpcDialogs` 的 `ctrl` 指向**已完整定义**的实例）

**⇒ 顺带拿到的高价值事实**：原版取 NPC vo 的正规 API 是
`SceneModel:getInstance():getScene():getNpcByBid(bid).vo`（不是遍历 `npcList`）。

## ④ 等级够但功能未解锁 —— ★ **机制已查清（本轮突破）**

### 取证：找到了原版的"功能开启"配置表

**`assets/src/config/config_function.luac`（19,233 字节）** —— `Config.Function`，共 **91 个功能**，
每项字段（从 `TDUP` 常量直读）：

```
description    功能名（技能 / 背包 / 阵型 / 伙伴 / 角色 / 好友 / 市场 / 帮会 / 任务 / 打造 / 队伍 / 系统 / 制作 / 成就 …）
module_flag    模块标识（skill / bag / formation / hero / role / friend / market / guild / mission / smith / team / set / hecheng / chengjiu …）
open_lev       ★ 开启等级
location       位置（1 / 2 / 3）
show_tips      "功能没有开放"
open_tips      "功能没有开放"
fight_sort_id  /  sort_id   排序
```

**抽样值**：

| 功能 | module_flag | **open_lev** |
|---|---|---|
| 背包 | bag | **1** |
| 技能 | skill | **4** |
| 伙伴 | hero | **5** |
| 市场 | market | **15** |
| 成就 | chengjiu | **15** |
| 帮会 | guild | **20** |

| 制作 | hecheng | **30** |
| 阵型 / 角色 / 好友 / 任务 | formation / role / friend / mission | **0**（默认开） |

### ★ 结论（`CONFIRMED`）

**功能是否"解锁"由客户端**本地**按 `Config.Function[模块].open_lev` 与**玩家等级**比较决定 ——
**不需要服务端下发任何"功能开关"。**

**⇒ 所以"等级已经足够了，但是相关功能还未解锁"，**不是等级本身的问题**。只有两种可能：**

1. **客户端读到的等级不是我们下发的那个**（待验证）
2. ★ **更可能：按钮其实已经"开放"，但点进去面板是**空的** ——**
   因为那些功能的协议（`10800 / 11300 / 11301 / 11700 / 128xx / 134xx / 105xx / 106xx …）
   **全部无人应答** ⇒ 用户感知为"没解锁"
