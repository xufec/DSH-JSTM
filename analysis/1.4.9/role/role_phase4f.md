## 二、协议证据

### `CS_10204` / `SC_10204`（1.4.9 定义，`tools/show_cmd.py 10204` 复核）

```
CS_10204: x:uint16, y:uint16            ← 只有 2 个字段（4 字节）
SC_10204: rid:uint32, srv_id:string, x:uint16, y:uint16
```

### ⚠ 重要观察：客户端**实际发 8 字节**，尾部是残留

```
>> cmd=10204 ? body(8)=00 68 00 26 03 e9 00 01      (x=104, y=38, 尾部 03e9 0001)
>> cmd=10204 ? body(8)=00 69 00 21 13 8f 00 00      (x=105, y=33, 尾部 138f 0000)
```

- 按定义只有 `x`/`y` 4 字节有效，**尾部字节每次都不一样** ⇒ 这就是既有的
  **dirty-tail（定长缓冲残留）** 特性。
- **服务端严格按定义只读 `x`/`y`、忽略尾部** ⇒ 解析出的坐标与 DB 完全一致，
  **该已知坑没有复发**。

### `dir` 的情况（如实说明）

`CS_10204`/`CS_10205` **都不带 `dir`** ⇒ 移动路径上 `dir` **没有来源**，
所以 DB 里 `dir` 保持 0 是**符合协议**的，不是 bug。
（`dir` 出现在 `1110` 的角色列表与 `10201` 的场景列表里，不在移动协议里。）

## 五、四项待办 —— 逐项查证结果（本轮补齐）

### ① `dir` 无来源 → **已确认为协议设计，不是"没找到"**

扫全协议表（`protocol/fields.json`，3553 条消息），找**字段名为 `dir`** 的消息：

```
CS（客户端→服务端）里带 dir 的：  0 个      ← 客户端从不主动上报方向
SC（服务端→客户端）里带 dir 的：  10200 (SCRoleEnter_10200)、10212
```

**⇒ `dir` 是纯服务端下发的字段**，客户端在移动路径上**根本不发送方向**。
所以 DB 里 `dir` 保持 0 是符合 1.4.9 协议的结果，
**想要方向只能由服务端自己设定（在 `10200`/`10201` 里下发）**，无法从客户端行为取得。

### ② 新手欢迎语 → **已定性：聊天控制器的固定欢迎语，与"首次登录"无关**

全 APK 搜该字符串，唯一命中：

```
game/chat/chat_ctrl.luac  proto[8] = ChatCtrl:initData  @144
    "欢迎来到{0}!!! <img src='{1}' scale='0.8' />"
```

- `{0}` = 游戏名（「绝世唐门」），`{1}` = 图片资源；
- 位置在 **`ChatCtrl:initData`**（聊天控制器初始化）里 ⇒ **每次初始化都插一条**，
  **不是"首次登录"标记**。

**⇒ 观察项可以结案：正常现象，不是异常。**

### ③ `hp/max_hp/mp/max_mp` 未使用 → **已查明：1.4.9 的角色侧没有这些字段的来源**

同样扫协议表：

| 字段 | CS（客户端会发） | SC |
|---|---|---|
| `hp` | **无** | `magic_play` / `summon_play` / `30205`（**战斗相关**） |
| `max_hp` | **无** | `18750` / `18760` / `30205` |
| `mp` | **无** | **无（协议里不存在）** |
| `max_mp` | **无** | **无（协议里不存在）** |

**⇒ 没有任何 CS 会上报它们**；`hp/max_hp` 只出现在**战斗类 SC** 里（而战斗系统本阶段
明令禁止开发）；`mp`/`max_mp` 在整个协议表里**根本不存在**。

**⇒ 结论（如实）：`roles` 表里这四列是"按阶段要求建的预留列"，
在 1.4.9 的角色基础协议里没有出处** —— 不填是对的，**不应为了让表"看起来完整"而编造值**。
（角色血量上限在 1.4.9 里走的是 `SC_10303.attr.hp_max`，即我们已实现的属性表。）

### ④ `scene_id` 多场景 → **已查明场景有 124 个，但本轮仍未跨场景验证**

`config_map.luac` 里的地图（共 **124** 个，节选）：

**⇒ 场景远不止一个，`scene_id` 持久化是有实际意义的。**

**但本轮仍未做"跨场景"验证**，原因如实说明：多数场景是**副本 / PVP / 活动**场景
