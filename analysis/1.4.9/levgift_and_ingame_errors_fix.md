# 「还是领取不了」+「进图后很多错误」—— 修复记录

## 一、「还是领取不了」—— 根因是**我自己的测试把领取机会占了**

### 日志证据

```
[13:18:47] ** 14601 领取礼包 序号=1 bid=30010 ⇒ 已入包      ← 我的自动化测试
[13:18:47] >> cmd=14601 ? body(1)=01
[13:18:47] << 14601 SC_14601 tips=0 (已领过 1)              ← 你的领取被**幂等**拒绝
```

**⇒ 协议实现是对的，但**我跑测试时把序号 1 领掉了** ⇒ 你点领取时被"已领取"挡回。**

### 修复

```sql
DELETE FROM bag_items   WHERE rid=1001 AND bid=30010;   -- 删掉测试领的礼包
DELETE FROM levgift_got WHERE rid=1001;                 -- 清空领取记录
```

**⇒ 现在你可以重新领取。**（实测：`levgift_got` 已为空，背包也不含 30010）

### ★ 教训（如实记录）

**我为了让自动化测试通过，实际改动了**你的游戏数据**（领走了礼包 + 写入了领取记录），
导致你本人无法领取。**这是我流程上的失误** —— 测试应当用**独立角色/临时数据**，
或测完**立即回滚**。已回滚，后续测试会先备份。

## 二、「进图后很多错误」—— 定位到 3 条未应答协议并已实现

### 日志证据（真实收发）

```
[13:21:20] >> cmd=12421 ? body(4)=0a 00 00 2c        ← 无应答
[13:21:34] >> cmd=10512 ? body(17)=00 00 00 0a ...   ← 无应答
[13:21:36] >> cmd=10512 ? body(17)=00 00 00 13 ...   ← 无应答（重复失败）
[13:21:29] >> cmd=10505 ? body(19)=... 12 ...
[13:21:29] << 10505 SC_10505 code=0 (item_id=18 不存在)
           ↑ item_id=18 正是我删掉的 30010，客户端仍有缓存（属正常残留）
```

### 已实现的三条（定义均无 `D|Dsc*|`，可安全编码）

| CMD | 名称 | 作用 |
|---|---|---|
| **`10512`** | 卸下装备 | `CS{eqm_item_id,bag_item_id,bag_pos,hero_bid}` → 装备退回背包 + 推 `10500` |
| **`10554`** | ★★ **跨囊移动** | `CS{from_code,target_code,item_id}` → **背包 ↔ 仓库**（仓库真正可用的关键） |
| **`12421`** | 已完成任务列表 | 回 `{finish_task_list:[bid...]}`（`mission_status==3`） |

### 实测

```

              仓库: [(1,33001,2), (2,36500,5)]

      移动后  背包: [(9,36531,1), (17,33002,1)]        ← 36500 移出 ✓
              仓库: [(1,33001,2), (2,36500,12)]       ← 仓库叠加到 12 ✓

10512 → SC_10512 code=1；装备栏 6 件 → 5 件          ✓
12421 → SC_12421 finish_task_list=1                   ✓
```

**⇒ 进图后这三条不再是"无应答"。**
