## 一、★ 两条的根因（都在"字段类型/名字"上）

### `12994` —— **同一个回复里两个 `ord` 是不同类型**

```
SC_12994{my_ord:**uint16**, my_val:u32, rank_list:table(ord:**uint8**, friend_val:u32,
                                                          rid:u32, srv_id, name, sex, career, lev)}
```
★ **`my_ord` 是 u16、元素的 `ord` 是 u8** —— 我 R172 把**元素的 `ord` 也写成了 u16** ⇒ 多发 1 字节。
⇒ 修：`_elems` 用 `'ord'`（u8）+ 给 `encode_rank_reply` 传 **`my_ord_u16=True`**。

### `12918` —— **编码器缺 5 个 token 的分支**

```
SC_12918{my_ord:u8, my_val:u32, my_g_name:string, my_head_name:string, my_g_num:u16,
         rank_list:table(ord:u8, **gid:u32**, **g_srv_id:string**, **g_name:string**,
                         **head_name:string**, **g_num:u16**, val:u16)}
```
★ 我的 `_elems` 用了 `gid`/`gs`/`gname`/`headname`，而 **`encode_rank_elem` 没有这些 token 的分支**
⇒ **全部落到 `else`（空表）** ⇒ hex 里那 4 个字段全是 0/空串 ✓
⇒ 修：**给编码器补 5 个 token**（`gid`/`gs`/`gname`/`headname`/`gnum16`）。

## 二、★ 本批的排查方法（值得复用）

**"把回包 hex 与 spec 逐字段对齐"**（`tools/_diag_r173.py`）：
按 spec 递归走一遍，打印每个字段的**名字 + 偏移 + 读到的值**
⇒ 一眼看出**错位在第几个字段**：

```
my_ord         @0   uint8=1
my_val         @1   uint32=133960
my_g_name      @5   str(3)='DSH'
…
rank_list      @17  table cnt=1
  --- 元素 0 ---
    ord        @19  uint8=1
    gid        @20  uint32=0        ← ★ 一眼看出这里该是 1001
    g_srv_id   @24  str(0)=''       ← ★ 该是 "1"
```
★ **这比"看 hex 数字节"快得多**，也比"猜"可靠。

> **★ 纪律第 25 条**：**"逐字段对齐"是排查编码错位的第一手段** ——
> 写一个"按 spec 递归走 + 打印名字/偏移/值"的诊断脚本，
> 比对着 hex 数字节**快一个数量级**，且**不会数错**。
