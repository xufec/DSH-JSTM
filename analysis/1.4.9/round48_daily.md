## 一、方法：用 adb 驱动 MuMu 真机

```
adb connect 127.0.0.1:7555        → device（与 emulator-5554 是同一实例）
包名 com.shiyue.dldl.ewan.qihoo
截屏 adb exec-out screencap -p    → 2560×1440 横屏
点击 adb shell input tap X Y
```

**取数过程**：主城截图 → 识别左上竖排第一个按钮为「日常」→ 点在 **(128, 240)**
→ 服务端立刻收到：

```
>> cmd=13781 ? body(4)=01 00 00 00     << 13781 SC_13781 huoli=0 list=0 lingqu=0
>> cmd=13786 ? body(4)=01 00 00 00     << 13786 SC_13786 week=0 richang=0 status=0
```

面板截图显示 **6 个任务**（学院任务 0/10 活力 0/70、监察任务 0/50 0/140、斗魂场 0/5 0/50、
封神之路 不限、宝图任务 0/10、极地寻宝 0/1 0/88）+ 底部"拥有活力 0/1420"。

★ **服务端回 `list=0` 时客户端仍显示完整任务列表** ⇒ **任务定义在客户端本地配置里**。

## 二、★ 找到权威任务表：`config_richang.luac`

`tools/extract_richang.py` 抽出 **43 条面板条目 + 17 条口径条目**。表里其实有**两类记录**：

| 类 | 代表字段 | 用途 |
|---|---|---|
| 口径类 | `{id, name, max_num, limit_lev, ord}` | 任务口径（`id` 即 `huoli_id`） |
| 面板类 | `{id:208, name:'学院任务', huoli_id:1, type_name:'日常任务', max_num:10, ord:1, ico, desc*}` | 面板显示条目 |

**与真机截图逐项核对（全部吻合）**：

| 任务 | 截图 | 配置 `max_num` |
|---|---|---|
| 学院任务 | 0/**10** | 10 ✓ |
| 监察任务 | 0/**50** | 50 ✓ |
| 斗魂场 | 0/**5** | 5 ✓ |
| 封神之路 | **不限** | 999 ✓ |
| 宝图任务 | 0/**10** | 10 ✓ |
| 极地寻宝 | 0/**1** | 1 ✓ |

⇒ 表找对了；`SC_13781.huoli_list{id,num,val}` 的 `id` 取 **`huoli_id`**
（三方一致：口径类 `.id` == 面板类 `.huoli_id` == huoli_id）。

## 四、★ 一个精确的否定结论：`num` 不是"次数"

我给 `huoli_list` 发的是 `{id:1, num:1, val:10}`：
- **活力**跟着变成 10 ✅
- 但**次数仍显示 0/10** ❌

⇒ **`SC_13781.huoli_list[].num` 不是面板上的"次数"**，次数来自**另一条消息**——
最可能是 `SC_13786.richang_list{id:H, num:H}`。

已按"一次一个变量"改写 `13786`（`richang_list` 用**面板 id 208/205/…** + DB 次数，
`status_list` 先留空），但 **尚未取到验证结果**（见 §五）。

## 五、★★ 事故与恢复：真机 ANR（含一条重要运维纪律）

调试中真机出现 **"绝世唐门没有响应"** ANR 弹窗，且**不会自动消失**。

**归因（有证据）**：**不是**我的 `13786` 改动引起的 ——
服务端日志显示**重启后客户端根本没再发过 `13786`**（最后一次 `13786` 是 17:46:04，
而重启发生在 17:46:52）⇒ 新代码**从未被执行**。

**最可能的真因**：**我在客户端正开着面板、等应答时重启了服务端** ——
连接被切断而客户端阻塞在等回包。

**恢复动作**（已完成）：
```
adb shell am force-stop com.shiyue.dldl.ewan.qihoo
adb shell monkey -p <pkg> -c android.intent.category.LAUNCHER 1
→ 标题界面 → 点"进入游戏"(1280,1000) → 已回到主城，心跳恢复
```
**已确认玩家回到主城**，角色 `DSH` 可见，UI 正常。

> ★ **新增运维纪律**：**不要在客户端处于"面板已打开 / 正在等应答"时重启服务端**。
> 这与之前那条"有真机玩家时不要跑 `replay_captures.py`"是同一类约束。
> 安全的重启窗口：客户端停在**标题界面**、或长时间无发包时。
