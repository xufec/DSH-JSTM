## 五、已知风险（如实标注）

1. **商城 `pay_type` → 币种：已按客户端权威表定死（2026-09-18 第三轮）。**
   依据：客户端 `common_function.payTypeEnToCode(pay_type) = Config.AssetsEnToCode[pay_type] or 1`
   （proto#69，7 条字节码），而 `AssetsEnToCode` 已从 `config_game_data.luac` 原样 dump
   （`1=gold 2=coin 3=coupon … 24=guild_active … 31=arena_soul … 40=rune_chip`）
   ⇒ `pay_type` 与资产 code 同源。服务端优先级已是 **配置 > 同源表 > shop_pay_asset**。
   实测：`3001`(pay_type=24) → `guild_active −6`；`4001`(pay_type=2) → `coin −4000`。
   ⚠ 更正记录：旧表缺 `24`（15 件公会商品会错扣银魂币）、把 `31` 写成 `zhuangshi`
   （把 `PathTool.getMoneyIconRes` 的**图标资源名**当成了**资产字段名**）。
2. **`10397` 有分支但不应答**（源码仅记录）；`15801` **故意**不应答
   ⇒ 对应面板必然为空（功能缺口，但应答会让客户端弹框，故保持不应答）。
3. **TCP 间歇断连根因未定位**（多轮出现，客户端重连后仍能进图）。
4. **战斗数值不可校准**：`Config.Mon` 无 HP/攻击/经验/金币字段（客户端无此数据），
   当前数值为 `TEST_ONLY / IMPLEMENTATION_FALLBACK`。
5. **怪物摆位坐标为 `emulated`**（原版布置表不在 APK），不得表述为原版坐标。
6. **货币语义已定死**（2026-09-18 复验）：钻石=`gold`(1)、**金魂币=`coupon`(3)**、**银魂币=`coin`(2)**。
   ⚠ 由此推论：任务奖励 `award_assets {2,n}` 落在 `coin` 列 ⇒ 界面显示为**银魂币**。
   详见 `analysis/1.4.9/task/task_reward_currency.md` 文末「复验」。
7. 客户端 **10102 未实测**、`10205` 未请求 ⇒ 这两条链路不能算已验证。
