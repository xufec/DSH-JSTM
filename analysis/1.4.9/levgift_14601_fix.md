# 「10级礼包领取不了」—— 已修复

## 一、取证链（每一环都有字节码或数据依据）

### 1.1 物品：`30010 = 10级礼包`

```
bid=30010  type=6  lev=10  name='10级礼包'
```
**⇒ 领取前它**根本不在背包里**（`SELECT ... WHERE bid=30010` 为空）。**

### 1.2 客户端模块：`game/dailysign/levgift_panel.luac`（等级礼包面板）

**⇒ 该面板属于 `dailysign`（签到/等级礼包）模块。**

### 1.3 协议注册处：`game/dailysign/dailysign_ctrl.luac proto[2]`

```
14100 on14100   ✓已实现      14101 on14101
**14600 on14600  ← ★ 未应答**  14601 on14601  ← ★ 未应答
10945 on10945   17600/17601/17602   16903/16904   19600~19604
```

### 1.4 协议定义（`cmd_resolve`，无 `D|Dsc*|` 子表 ⇒ 可安全编码）

```
CS_14600（空）        → SC_14600 { days:u16, get_day: table(type:u8) }
CS_14601 { days:u8 }  → SC_14601 { tips:u16, msg:string, days:u8 }
```

**⇒ **`14601` 就是"领取"**。客户端发它、服务端**没有这条分支** ⇒ **无应答 ⇒ 领取不了**。**

## 二、★ 礼包 bid 的对应关系（**可查证的规律，不是猜**）

从物品表逐条核对名称：

```
30010 = '10级礼包'      30011 = '20级礼包'      30012 = '30级礼包'
30013 = '40级礼包'      30018 = '50级礼包'      30014 = '宗门礼盒'
```

**⇒ 等级礼包按等级递增 ⇒ 序号 → bid 做成**配置项** `levgift_rewards`，
并注明「序号与等级的精确对应**待实机验证**（若不对改这里即可）」。**

## 三、实现

| 组件 | 内容 |
|---|---|
| **`14600`** | 回 `{days, get_day:[未领取的序号]}` |
| **`14601`** | 领取：查配置 → 校验未领过（**幂等**）→ 发礼包入包 → **推 `SC_10500`（背包刷新）** → 回 `{tips=1, msg='', days}` |
| **`levgift_got` 表** | 记录已领序号 ⇒ **持久 + 防重复领取** |

```json
"levgift_days": 5,
"levgift_rewards": {"1":30010, "2":30011, "3":30012, "4":30013, "5":30018}
```

## 四、实测（独立 TCP）

```
SC_14600 days=5 get_day(可领)=[1,2,3,4,5]
领取前背包: [(8,36500,7), (9,36531,1), (17,33002,1)]

领取 序号=1（10级礼包 30010）→
   ← 收到 10500 背包推送
   SC_14601 tips=1 msg='' days=1
领取后背包: [..., (18, 30010, 1)]        ← ★ 10级礼包入包

重复领取 → SC_14601 tips=0 msg='已领取'   ← 幂等 ✓
```

**⇒「10级礼包领取不了」已修复。**
