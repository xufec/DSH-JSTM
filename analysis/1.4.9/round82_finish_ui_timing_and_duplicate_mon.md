## 一、★★ ① 没有结算界面 —— `SC_20023` **发得太晚（3 秒）**

### 1.1 真机日志（决定性）

```
[19:41:34] >> cmd=20002  →  << 20002 code=1 mon=10105(圣灵教精英)
[19:41:34] << 20010 SC_20010 battle init fighters=2
[19:41:40~42] >> cmd=20014 ×4            ← 客户端动画播完
[19:41:45] << 20020 SC_20020 result=1     ← 战斗结果
[19:41:46] >> cmd=20021                   ← ★★ 客户端**立刻**发 csCloseFinishView（关结束界面）
[19:41:48] << 20023 SC_20023 ...          ← ★ 结算明细到得太晚，**界面已关**
```

`battle.luac` proto#11 也印证：客户端在拿到 `result` + `finish_data` 后会
`Fire(EXIT_FIGHT, result, isWin)` 并 `Fire(SHOW_UI, true)` —— **界面由 `20020` 立即触发**，
而**内容来自 `finish_data` = `SC_20023`**。

⇒ 我们把 `20023` 放在 **3 秒后的定时器**里发（原注释："等客户端回 20014 再发明细"），
真机上客户端**不等** —— 收到 `20020` 就关界面，明细到达时已无用。

### 1.2 修复

`SC_20020` 之后**立即同步**发 `SC_20023`（战败时再跟着发 `SC_20022`），
把"经验/金币/落库"这些**不影响界面**的结算仍留在定时器里：

```python
send(20020)                       # 胜负
send(20023, bt.build_20023())     # ★ 紧跟，同一 tick
if result != 1: send(20022, ...)  # 战败才发（openBattleFail）
self._battle_settle_after_3s()    # 只做奖励/落库
```

> `_battle_settle` 里保留一条**兜底**：万一即时发送失败，它还会补发一次。

## 二、★★ ② 两个重叠的怪 —— 是我 R76/R77 的**双路径**造成的

圣灵教精英现在会由**两条路各建一只**：

| 路 | 来源 | 效果 |
|---|---|---|
| A | `SCMapGird_10201.mons`（R76/R77 加入） | 走客户端的**正常网络路径** ⇒ **可见**（R75 探针证明另一条路不可见） |
| B | `SC_15402` → 客户端 `createMon()` → `SCENE_CLIENT_ADD` | 绑定 `mis_key`/任务，但**视图层不建精灵** |

两条都生效 ⇒ **屏幕上两只重叠**。

### 修复：只保留可见的那条（A）

```json
"guaji_push_15402": false,
"guaji_push_15402_on_enter": false,
"guaji_auto_start": true          // 保留：仍要自动把玩家送进 10005
```

⇒ 怪只由 `10201.mons` 下发（可见），点击走 `CS_20002`（R77 已修好）→ 战斗 → 结算；
任务击杀进度由 `_battle_settle` 处理（不依赖 `15402`）。

> `guaji_push_15402` 的开关与代码**都保留**，置 `true` 即可回到双路径（对照实验用）。
