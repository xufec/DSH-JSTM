## 三、★ 一次"号段一刀切"的自纠（**又一次**纪律第 10 条）

我第一版用 **`if cmd // 100 == 107`** 一刀切，把"其余"都按 `{code,msg}` 处理。
**结果 8 条越界**：

```
✗ 10754 len=3 消耗=2 err=upgrate_time_list[].props_id: 越界
✗ 10755 … make_time_list[].props_id: 越界
✗ 10757 … look_queue_list[].queue_type: 越界
✗ 10761 len=3 消耗=1 err=can_get: 越界
```

**根因**：`107xx` 有 **17 种 SC 模式**，而我的 `else` 分支只覆盖 `{code,msg}`。

**⇒ 修**：把 8 条**逐条按各自 SC 编码**（先打印精确 SC 再写）：

| cmd | SC | 处置 |
|---|---|---|
| `10733` | `{code,msg,set_house_hero_return:table<Type,hero_list>}` | 空表 |
| `10741` | `{lev,status,flag,time,all_time:u32,can_get,be_rob}`（7 字段）| 全 0 |
| `10744` | `{code,msg,wood:u32}` | 回真实木材 |
| `10751`/`10754`/`10755`/`10757` | `{…:table<…>}` | 空表 |
| `10761` | `{lev:u8, can_get:u32, be_rob:u32, next_time:u16}` | 全 0 |

**修后**：`107xx 26 条：FAIL 0` ✓

> **★ 纪律第 10 条（再强调）**：**"按号段/按家族"只是"找候选"的方法，
> 绝不能当"编码"的方法** —— 编码必须**逐条**。
> ★ 一个"看似同族"的家族里，**SC 模式可能有十几种**。
