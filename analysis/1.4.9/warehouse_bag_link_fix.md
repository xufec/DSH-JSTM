# 「仓库背包不互通」—— 已修复（真机数据定位）

## 一、真机取证：你已经用过，日志留下了完整证据

```
[13:43:07] >> cmd=10554 ? body(10)=01 04 00 00 00 02 2d 2d 2d 2d
[13:43:07] ** 10554 移动 bid=25890 x1 从囊1 到囊4        ← 服务端移动**成功**了
[13:43:10] >> cmd=10554 ? body(10)=01 04 00 00 00 02 ...
[13:43:10] << 10554 SC_10554 code=0 (item_id=2 不在囊 1)  ← 客户端拿**旧 id** 重试 ⇒ 报错
```

**⇒ 两层信息：**
1. **`body` 是 **10 字节**（规范只写 6 字节：`from:u8, target:u8, item_id:u32`），后面还有 4 字节 —— 但不影响解析（我只读前 6 字节）**
2. **服务端**移动成功了**，但**客户端本地状态没更新** ⇒ 它用**旧的 item_id 重试** ⇒ 看到 `code=0` ⇒ 用户感知为"不互通"**

## 二、★ 根因：推送用了**请求-应答型**协议

### 客户端代码（`game/warehouse/warehouse_ctrl.luac`）

```
warehouse_ctrl proto[2] cmd=10554  ->  moveItemHandler
moveItemHandler (proto[4], 18 条):
   @0  resp.code / @1 ISNEN / @2 JMP        -- 成功才继续
   @3  BackPackCtrl:getInstance():getData()
   @11 'moveItem'  / @13 CALL               -- ★ 靠这个做**本地**状态更新
   @14 'message' / @15 resp.msg / @16 CALL
```

**⇒ 客户端**靠 `moveItem(...)` 更新本地**；一旦本地没更新，后续操作全用旧 id。**

### 我的错误

**原实现在移动后主动推的是 `SC_10502`** —— 而 `10502` 是**请求-应答型**协议：
**客户端**只在主动发 `CS_10502` 后**才处理 `SC_10502`**，**主动推的会被忽略** ⇒ 本地不更新。**

## 三、修复

**改用**主动推送型**协议告知"源囊删了一件、目标囊加了一件"：**

```python
# 源囊：告知删除
self.request.sendall(pack_frame(10503, w_u8(frm) + w_u16(1) + w_u32(item_id)))
# 目标囊：告知新增（只发这一件）
self.request.sendall(pack_frame(10500, w_u8(to) + build_bag_items(cur[:1])))
```

**依据：`10500`（`SCAddRoleBag`）与 `10503`（`SCDelItems`）都是**服务端单向推送**语义
（`manual.md` 里它们**只有 SC、没有 CS**）—— 这正是"服务端主动刷新客户端"的正确通道。**
