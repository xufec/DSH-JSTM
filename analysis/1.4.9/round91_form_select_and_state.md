## 三、★★ 另一个可疑点：`10401.hero_bag[].state` 我们**恒发 0**

从客户端字节码看：

- `hero_data.luac`：`hero_list` 的元素是 **`HeroVo`**（`setValueByKey` 逐字段赋值）；
- **`HeroVo` 的字段表（28 个）里没有 `state`**：
  `skill_attr / equip_attr / hero_attr / skills / power / chip / star_lev / color / career /
   exp / exp_max / exp_total_nextlev / lev / …`
  ⇒ `state` 是 **`HeroData` 的独立字段**（由 `changeHeroSatus` / `10414` 那条线维护）；
- 我们 `10401` 的 `state` **永远是 0** —— 如果客户端用它过滤"可用伙伴"，列表就会空。

**处置（按纪律：不猜死值，做成可实验的配置）**：

```json
"hero_state": 1        // config.json，可改 0/1/2 一次实验判定
```

`10401` 的 `state` 现在读这个配置（**原恒 0**）。实测已生效：`SC_10401 首条 state = 1`。

> ⚠ 这是**一次实验**，不是定论 —— JSON 里写了 `hero_state_note` 说明它的来历与未取证状态。
