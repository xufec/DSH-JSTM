# 第十九轮：战力闭环 —— 根因定位与诚实结论

> 用户指定：解 `config_role_career` 职业 attr → 填充属性向量 → 让战力非零。

---

## 一、本轮取证结论

### 1. 职业 `attr` 是**空表**（TNEW）

```
config_role_career proto[0]：
  @8  TDUP arr=11 → skill_list      ← 职业 1(玄武) 11 个技能
  @10 TDUP arr=2  → born_skill_list
  @12 **TNEW**    → attr            ← ★★ 构造时是空表 {}
  @14 TNEW        → turn_career_attr
  （6 职业：5 个 11 技能，career 9 测试 6 技能）
```
**⇒ 职业基础属性字段 `attr` 不是在配置表里给死的，而是**由别的数据/函数填充**（等级成长）。**

### 2. 每级属性成长表**未直接找到**

`config_role_attr` = 等级升级表（`exp_total/exp_max/sinew_max/attr_point`），**不含 atk_s/hp_max**。
`config_attr` = 属性**定义/战力权重**（id/key/str/power）。
**⇒ 没有一张表直接给出"每级 atk_s 加多少"** —— 这是客户端 `CalAttr` 在运行时算的。

### 3. ★ `10302/10303` **不下发属性向量**（决定性发现）

```
build_10302 键: rid/name/lev/career/sex/vip/volumes/attr_point ...
build_10303 键: rid/name/lev/career/mspd/vip_exp ...（同，无 atk_s 等）
**⇒ 服务端当前下发的消息里，根本没有 atk_s/hp_max/dodge/crit 这 64 项属性的值。**
```

**⇒ 战力 = 0 的**最终根因**：不是权重、不是公式、不是职业表 —— 而是**
**服务端根本没有下发过属性向量**，所以客户端/服务端都无值可算。**

## 二、★ 战力闭环的**真正卡点**（诚实）

我已经交付：
- ✅ **战力权重**（`config_attr` 的 `AttrPower`，64 项，原版）→ `server/power.py`
- ✅ **战力公式**（Σ 属性×权重）+ `/DSH_ADMIN/power` 接口
- ✅ **职业表 / 等级表 / 属性定义**全部从 APK 提出

**但"属性向量"这个输入，服务端目前没有来源：**
- 客户端运行时 `CalAttr` 算（服务端复制公式才能对得上 —— 需逆出成长公式，**工作量大**）
- 或别的 CMD 携带属性（**本轮未定位到**）

**⇒ 我**没有**让战力非零。** 因为那需要先逆出**客户端角色属性的完整计算**（基础+等级成长+装备+加点），
这超出本轮容量，且我不愿**编造一个假的属性向量来凑非零战力**（违反实事求是原则）。
