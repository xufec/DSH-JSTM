## 一、★★ 上一轮的挂钩写错了：`mission_type` 根本区分不了线

上一轮我用 `config_mission.type == 1` 当作"学院线"，**这是错的**：

```
== mission type 分布 ==
  type=1    262 条   例: (10010 斗罗魂师) (10020 切磋魂技) (10030 武魂觉醒)
                         还有 10940 监察团 / 10340 斗魂场 / 10641 封神之路 …
```

**`config_mission` 的 262 条任务全部是 `type=1`** ⇒ 按 type 匹配会把
**任何**任务提交都记成"学院任务"（连监察团、斗魂场、封神之路都算）
⇒ **等于伪造进度**，正是本项目最忌的那类问题。

### 为什么配置里推不出分组

| 追问 | 结果 |
|---|---|
| `trigger_fun`（hongchen / zhuoyao / 7）是任务字段吗？ | **不是** |
| `hongchen`/`zhuoyao` 到底是什么 | 客户端 `ghost_ctrl` 里的 **`mon_hongchen` / `mis_hongchen`** —— **挂机(魂灵)事件处理器名** |
| `config_mission` 有指向 `huoli_id`/成就 `bid` 的字段吗 | **没有** |

⇒ "学院任务/监察任务"是**挂机线**，归属由**客户端挂机逻辑**决定，
服务端配置里**没有被显式表达** ⇒ **不存在"自动从配置推映射"的路径**。

## 二、改法：显式 bid 白名单 + 热重载 + 安全默认

| 改动 | 说明 |
|---|---|
| **匹配方式** | `mission_type` → **显式 `mission_bids` 白名单**（精确、可审计） |
| **未命中行为** | **什么都不做**（安全默认：宁可不动，不可错记） |
| **映射表热重载** | `chengjiu_map()` 按文件 **mtime** 重载 ⇒ **补一行 JSON 不需要重启服务端**（也顺带符合刚立的"重启窗口"纪律） |

```python
def credit_mission_done(cfg, rid, mission_bid):
    for g in chengjiu_map():
        if int(mission_bid) not in [int(x) for x in (g.get('mission_bids') or [])]:
            continue                      # ★ 白名单命中才动，否则什么都不做
        db_daily_add(rid, int(g['panel_id']), 1, 0)      # 日常『次数』+1
        for b in g.get('ach_bids') or []:
            db_chengjiu_add(rid, int(b), 1)              # 成就进度 +1
        return ...
    return None, []
```

**`[1]` 这条最有价值**：它**专门用来钉住"按 type 匹配"那个错误**——

**过程中修掉两个自己的测试缺陷**（都记在案）：
1. 第二次提交同一任务会走**幂等分支**（`already committed`）⇒ 挂钩根本到不了；

   ⇒ 最终改为"清掉该角色的任务行 + 复用可提交的 `10010`"。
