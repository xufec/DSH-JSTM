# 10511 穿戴装备 —— 已实现并验证

> 目标：实现客户端**唯一还没实现**的 105xx 协议 —— `10511`（穿戴装备）。

---

## 一、协议（`cmd_resolve_105.luac`，无 `D|Dsc*|` 子表 ⇒ 可安全编码）

```
CS_10511 { bag_item_id:u32, eqm_item_id:u32, hero_bid:u32 }
SC_10511 { code:u8, msg:string, is_auto:u8, bag_item_id:u32,
           eqm_item_id:u32, eqm_new_pos:u8, hero_bid:u32 }
```

**语义（从字段名 + 上下文）：** `bag_item_id` = 要穿的背包物品；`eqm_item_id` = 该槽原有装备（0=空）；
`hero_bid` = 伙伴（0 = 本角色）。

---

## 二、实现

### 新增：装备表 + 4 个辅助函数

```python
db_init_equip()          # 建表 equip_items(rid, slot, item_id, bid, hero_bid, ctime)
db_equip_all(rid)        # 取全部装备
db_equip_put(rid, slot, item_id, bid, hero_bid)
db_equip_take(rid, slot)         # 取下某槽，返回被取下的行
db_equip_free_slot(rid)          # 找一个空槽
```

### `10511` 处理逻辑

```
① 校验 bag_item_id 存在（不存在 ⇒ code=0 + 非空 msg）
② 从背包**移出**该物品
③ 若 eqm_item_id != 0：把旧装备**取下并放回背包**（换装）
④ 记入装备槽
⑤ 推送 SC_10500（背包刷新）+ SC_10503（删除告知）
⑥ 回 SC_10511{code=1, is_auto=0, ..., eqm_new_pos=0, hero_bid}
```

**⚠ 如实标注**：**装备槽位编号语义与原版属性加成未实现**（无取证）⇒
`eqm_new_pos` **回 0**，槽位从 1 起递增分配，**不自行发明槽位含义。**

## 三、实测（独立 TCP）

```
穿戴前 bag: [(5,36531,180), (6,33001,1), (7,33002,1), (8,36500,7)]   eq: []
穿戴   item_id=5 →
穿戴后 bag: [(6,33001,1), (7,33002,1), (8,36500,7)]      ← item5 移出 ✓
穿戴后 eq : [(1, 5, 36531, 0)]                            ← ★ 进入装备槽 1 ✓

换装：穿 item_id=6，eqm_item_id=5（把旧的换下）→
换装后 bag: [(7,33002,1), (8,36500,7), (9,36531,1)]       ← ★ 旧装备 36531 回到背包 ✓
换装后 eq : [(1, 6, 33001, 0)]                            ← 新装备 33001 在槽 1 ✓
```

**⇒ 穿戴 + 换装闭环完全正确。**

## 四、★ 本轮两个自查抓到的问题（如实记录）

### 1. 初始化没加上 ⇒ **物品丢失**

**我第一次用 `db_init()` 那行做锚点追加初始化，锚点字符串没匹配上**（`assert` 失败），
结果 **`equip_items` 表从未创建** ⇒ `db_equip_put` **静默失败** ⇒
**物品从背包移走了，却没进装备 —— 丢了。**

**⇒ 修复：**
- 用**正确的锚点**把 `db_init_bag_volume()` / `db_init_equip()` 加进 `main()`
- 并给 `db_equip_all/put/take` **都加防御性建表**（`db_init_equip()` 幂等）
  ⇒ **即使忘初始化也不会再丢失**
- **补回了丢失的那件物品**（bid=36500）

### 2. 我的验证脚本又一次偏移算错

`SC_10511` 在 `msg` 之后还有一个 `is_auto:u8`，我漏算了它 ⇒ 读成
`bag_item_id=0 / eqm_item_id=83886080`。
**⇒ 服务端编码是对的**（DB 状态已证明）；**错的是我的测试脚本。**
