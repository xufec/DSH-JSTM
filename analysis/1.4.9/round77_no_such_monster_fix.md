# R77：修复「点击圣灵教精英提示 `no such monster 10105`」

> 用户报障：**怪出现了**（R76 生效），但**点击无效**，提示 `no such monster 10105`。
> 那句英文**是我们服务端自己回的**。根因与修法如下，**已用脚本验证通过**。
> **时间**：2026-09-29 18:47 – 18:55。

---

## 一、定位：那句话是 `20002` 回包里的 msg

```
server/mock_server.py:7324
pkt = pack_frame(20002, w_u8(0) + w_str('no such monster %d' % mon_id))
```

真机日志（点击时）：

```
>> cmd=20002 ? body(8)=00 00 27 79 13 8f 00 00      ← 客户端点怪 → CS_20002{mon_id=10105}
<< 20002 SC_20002 code=0 (mon 10105 不在场景, 场景怪=[20001])   ← ★ 服务端用错了场景的怪表
```

`20002` 是"对怪物发起战斗"（`CS_20002{mon_id}` → `SC_20002{code,msg}`；`code~=TRUE` 时客户端 `message(msg)`）。

---

## 二、根因：校验用的是**固定出生场景**的怪表

```python
# 旧代码
sp_bid = int((self.cfg.get('spawn') or {}).get('bid') or 10001)   # ← 写死 10001
_npcs, _mons = scene_quest_extras(self.cfg, sp_bid)               # ← 10001 的怪 = [20001 戴浩]
if mon is None:
    ... 'no such monster %d' ...
```

玩家在**乾坤日月谷 10005** 点了 **10105**，服务端却拿**史莱克城 10001** 的怪表去比对
（那里只有戴浩 20001）⇒ 必然 `no such monster`。

**这是同一个 bug 家族的第 6 次复发**：「R73 修了"发出去的表不按场景"，但**校验侧**那条漏了」。

---

## 三、修复：两处

### 3.1 挂机怪并入"本场景的怪"（单一来源）

R76 我曾把挂机怪只加在 `_send_10200` 的**局部变量**里 ⇒ `20002` 校验时看不到它。
现在把它移进 `scene_mons()`：

```python
# scene_mons(cfg, scene_id) 末尾
_lev9 = int((role_state(cfg) or {}).get('lev') or ...)     # ★ 读实时等级，不读配置模板
_spot9 = guaji_spot_for_lev(_lev9) or {}
if _spot9['map_bid'] == scene_id:
    out.append({... 'id': _spot9['mon_bid'], 'name': '圣灵教精英', 'source': 'guaji'})
```

⇒ **`10201`（下发建精灵）与 `20002`（校验点击）现在读同一份列表**。
（顺带修掉一处 R56 同族隐患：等级改为读 DB 实时值。）

### 3.2 `20002` 改为**在"候选场景"里找怪**

```python
cand = [本连接最后进过的图(_last_enter), 存档场景, 出生场景, 该等级段的挂机图]
for c in cand:
    if 找到 mon_id: 用它
```

**为什么用"候选"而不是"当前场景"**：我一开始选了"落库当前场景"，结果实测发现
**客户端会用它自己的 `scene_id`（10001）上报位置，把 `roles.scene_id` 写回去** ——
两边互相覆盖，任何单一来源都不可靠。而"**玩家被我们送进过的图里能找到这只怪**"
才是这个校验真正要表达的语义。（落库那条已回退，不留副作用。）
