## 一、★ 本轮成果：商城列表用**真实数据**填充

### 发现

真机**一直在发** `13401` / `13403`：
```
>> cmd=13403 ? body(5)=02 66 00 00 13     ← type=0x02（后 4 字节是残留）
>> cmd=13401 ? body(8)=00 00 00 00 00 00 00 00
```

**协议定义**：
```
13403 CS{type:u8} → SC{type:u8, item_list:table(item_bid:u32, price:u32)}   ← 商品列表
13401 CS{type:u8} → SC{type:u8, buy_list:table(id:u16, buy_num:u16)}        ← 已购次数
```

**★ 关键：`type` 正好对应 `mall_config.json` 的 `type` 字段！**

```
mall_config.json（134 件真实原版商品）：
  type=2:   51 件   (25890@99, 25301@250, 36500@5 ...)
  type=3:   15 件
  type=4:   11 件
  type=5:   10 件
  type=6:   10 件
  type=20:  24 件
  type=100/101/102: 5/4/4 件
```

### 实现

```python
if cmd in (13401, 13403):
    mtype = body[0]                              # 只读第 1 字节（真机后有残留）
    goods = [g for g in mall_cfg() if g['type'] == mtype]
    if cmd == 13403:
        → SC{type, item_list:[(item_bid, price)]}   # ★ 真实 bid + 真实 price
    else:
        → SC{type, buy_list:[(id, 已购次数)]}       # ★ 已购次数查 mall_bought 表
```

**★ 注意**：这两个 CMD 原先在**通用默认响应集**里，而通用分支**位置靠前** ⇒
**必须把它们从集合移出**，否则会被通用分支抢先返回空表。已在代码里注明此坑。
