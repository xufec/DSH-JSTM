## 四、★★ 一处自纠（**"模块级 stdout 重设"导致 import 失败**）

★ 现象：`_fix_r235.py` **在 import `_move_out_tuple` 时就崩**（`ValueError: I/O operation on closed file`）⇒
   ★★ **根因**：`_move_out_tuple.py` **在模块级写 `sys.stdout = io.TextIOWrapper(sys.stdout.buffer, …)`**
      ⇒ **被 import 时**，调用方的 stdout 已被 pwsh 重定向/关闭 ⇒ **`sys.stdout.buffer` 不可用 ⇒ import 抛错** ❌
   ★★★ **后果**：**`move_out` 没执行** ⇒ **文件没改**（**而且看起来"插入成功"是假象**）❌

**修**：**把 stdout 重设移到 `if __name__ == '__main__':` 里** ✓

> **★ 纪律第 75 条**：**"工具脚本"被 import 时不能有"模块级副作用"** ——
> `sys.stdout` 重设、`os.chdir`、读写文件、打印 —— **都必须在 `__main__` 里**。
> ★★ **判据**：**"工具能被 `import` 而不抛错"** ⇒ 这是"可复用工具"的最低要求。
> ★★★ **本项目所有 `tools/*.py` 都应遵守**（**R192–R194 的 `config_deconstruct` 也栽过**）。
