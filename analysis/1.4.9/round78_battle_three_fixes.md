# R78：修复战斗三连问题（pos=0 / 怪模型同主角 / 胜利界面不对）

> 用户报障三条：① 点怪后提示 **`pos位置不能为0`**；② 圣灵教精英**战斗时模型和主角一样**；
> ③ **战斗胜利后胜利界面不对**。
> 三条根因**全部定位**，其中两条是明确缺陷、一条是**结构性缺失**。
> **时间**：2026-09-29 18:56 – 19:05。

---

## 一、① `pos位置不能为0` —— `pos` 是 **1 基**的

```python
# server/battle.py  Battle.__init__（旧）
self.role_f = Fighter(..., group=1, pos=0, ...)     # ← 我方
self.mon_f  = Fighter(..., group=2, pos=0, ...)     # ← 敌方
```

原注释写的是「我方 group=1 pos **0..2**」——**这个推断是错的**，客户端收到 0 直接弹错。

**修**：双方都改成 **`pos=1`**。

---

## 二、② 怪的模型和主角一样 —— `animate_res.ant_id` 写死 0

```python
# server/battle.py  Fighter.encode()（旧）
b += w_u16(1)          # animate_res 计数
b += w_u16(0)          # ant_id      ← ★ 写死 0
b += w_str(self.res_id)  # ant_val ← Config.Mon 的原版资源 id（如 H34800）
```

`ant_id=0` 很可能被客户端当成「**没指定外观**」⇒ 回退到角色默认模型，
于是 `ant_val`（`H34800`）**根本没被用上**，屏幕上就是主角的模型。

**修**：`ant_id` 由 `0` 改为 **`1`**（非 0），让 `ant_val` 有机会生效。

> ⚠ **诚实标注**：`ant_id` 的**语义仍属【待验证】**（可能是资源槽位 / 动画类型 id）。
> 本轮只是把它从"明显无效的 0"改成非 0；若客户端仍用主角模型，
> 下一步应反汇编 `battle.luac` 里 `animate_res` 的解析分支，而不是继续猜数值。

---

## 三、③ 胜利界面不对 —— **我们从来不發 `SC_20022`**

`protocol/fields.json`：

```
命令 20022
  - SC_20022（sc）
      | icon_list | table(icon_id:uint32) |
```

而 `analysis/1.4.9/battle/battle_flow.md` 的流程表里明确写着
**`20022` = 「显示战斗结束界面」**。而我们只发 `20020`（胜负）与 `20023`（明细），
**从未发过 `20022`** ⇒ 客户端收不到"可以显示结束界面"的通知 ⇒ 胜利界面自然不对。

**修**：结算时**补发 `SC_20022`**：

```python
_p22 = pack_frame(20022, w_u16(0))     # icon_list = 空表
```

> ⚠ `icon_id` 的语义**未取证** ⇒ 按纪律**发空表**，不编造奖励图标。
> 结构到位后客户端至少能走完"显示结束界面"这一步。
