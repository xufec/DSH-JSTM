## 一、`16200`（BOSS 列表）—— 有**真实配置**

```
SC_16200{count:u8,
         boss_list:table(mon_bid:u32, kill:u8, map_bid:u32, x:u16, y:u16,
                         left_time:u32, award:u8)}
```

数据源：`config_boss.Boss` —— **27 项**，每项都有 `boss_id` / `map_bid` / `boss_name` / `world_lev`…

| 字段 | 来源 |
|---|---|
| `mon_bid` | ★ **`boss_id`**（配置）|
| `map_bid` | ★ **`map_bid`**（配置，**27/27 全有**）|
| `kill` | 玩家是否击杀过 ⇒ **新建 `role_boss_kill`**；没有行 ⇒ 0（真话）|
| `x` / `y` | 配置里**没有坐标** ⇒ 0（诚实）|
| `left_time` | 刷新剩余时间 ⇒ 无源 ⇒ 0 |
| `award` | 首杀奖是否可领 ⇒ 未击杀 ⇒ 0 |

### ★★ 结构形态：**先离线验证，再写代码**（R128 的教训）

`SC{count:u8, boss_list:table(...)}` 里 `count` 是 `u8`，但 `table` 通常**另有 u16 计数**
⇒ 用 `tools/_probe_16200.py` 构造两版喂给 `parse_full`：

```
版本 A（count(u8) + u16 表计数 + 27×18 元素）: len=489 off=489 errs=[] ⇒ PASS ✓
版本 B（count + 直接元素，无独立计数）      : off=3            ⇒ FAIL
版本 C（count=0 + 空表计数）               : PASS
```

⇒ **正确形态是 A**（元素宽 = 4+1+4+2+2+4+1 = **18**）。

> ★ 这次**没有再猜** —— 先把"cnt 数什么"验证清楚。对比 R115b/R127c 白回退两轮，
> 这一条纪律的价值立刻兑现：**`16200` 一次就对**。

### 实测

```
SC_16200 len=489 消耗=489 err=None count=27 ⇒ PASS（27 条真实 BOSS）
```
