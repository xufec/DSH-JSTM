### ★ 重打包期踩到并修掉的坑（第二次重打包的原因）

`ghfight` 一次都没上报。原因：

```lua
sch:scheduleScriptFunc(fn, 3.0, true)   -- 第三参是 **paused**，不是 "只跑一次"！
```

传 `true` ⇒ 回调**永不执行**。改为 `false` + 闭包内 `fired` 标志保证只跑一次。
（`node tools/lua-check/check.js` 每次都过了 —— 语法没问题，是**语义**传错。）

## 三、★★ 结论 2：怪"看不见"的原因被探针直接指出来

```
t=ghvis &v=mon_id_10052_inScene_false
t=ghvis &v=mon_id_10052_tablesWithIt_NONE     ← 场景里**任何一张表**都没有它
```

⇒ `createMon()` 虽然走完、也 fire 了 `SCENE_CLIENT_ADD`，
**但视图层没有为它建精灵**（所以屏幕上什么都没有）。**功能通、画面不通。**

### 修法（R76）：让挂机怪走**场景网格**这条网络路径

`SCMapGird_10201.mons` 才是客户端建场景单位的**正常入口**。
所以进挂机图时，把该等级段的挂机怪直接放进 `10201.mons`：

```
[18:40:15] << 10200 SCRoleEnter (server push) bid=10005 (10,58)
[18:40:15] .. 挂机怪 10105(圣灵教精英) 放进 10201.mons @(10,58)（R76）
[18:40:15] << 10201 SCMapGird (server push) roles=1 npcs=3 mons=1 elems=2 (204 bytes)
```

怪的名字/资源来自 `Config.Mon`（`mon_def(10105) = 圣灵教精英 / H34800`），
坐标与 `10200` 给玩家的一致（**同一坑 R72 踩过一次，这次坐标直接复用 `_rx/_ry`**）。
