## 一、背景订正（用户已完成，我已核实）

依据用户的 `analysis/mission_protocol_verify.md`（反汇编 `mission_ctrl.luac proto[46] submitHandler`）：

```
resp.code == TRUE(1)  → 成功分支（mission_data:del / panel:update / Fire(UPDATE_MISSION)）
否则                   → message(resp.msg)     ← msg 为空 ⇒ **空白提示框**
```

**⇒ 本作 `TRUE == 1`（`common_define proto[7]` 也是 TRUE=1）。**
**原实现写反 ⇒ 成功时空白框、条件未满足时被当成功而误删任务。**

**已核实文件里 `12402`/`12403` 四处 `code` 均已是订正后的值：**

| 分支 | 现值 | 判定 |
|---|---|---|
| 12402 接取成功 | `w_u8(1)` | ✅ TRUE |
| 12403 提交成功 | `w_u8(1)` | ✅ TRUE |
| 12403 幂等（已提交） | `w_u8(1)` | ✅ TRUE |
| 12403 条件未满足 | `w_u8(0)` + 非空 msg | ✅ 失败 |
| 12403 任务不存在 | `w_u8(0)` + 非空 msg | ✅ 失败 |

**另外我自查修掉一个**自己引入的**新 bug**：`12402` 原取 `self.cfg['missions']`
（切到 APK 任务表后该键为空）⇒ **会回空列表**，已改为与 `12400` 同源的 `mission_rows()`。

**服务端干净重启**：`stderr 0 字节`、`mission config loaded: 846 条`。
