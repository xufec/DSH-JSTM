## 2. 结论一：`10010` 的 `progress` **确证为空**

两组独立实测（探针上报）：

```
t=misProg&v=progress_table_n0_type_1_status_1      ← 0 个条目
t=progStep&v=status_1_p_status_nil_keys_           ← 键列表为空
t=progStep&v=status_2_p_status_nil_keys_           ← 换 status 后仍为空
```

**⇒ `Config.Mission[10010].progress` 是**空表**（两种 status 下都如此）。**

> 静态反汇编里 `TSETS 'progress'` 附近出现过 `{'fight_mon',20001,1}` 这样的行，
> 但**运行期实测证明它不属于 `10010`**（探针读的就是 `10010` 的 `mis_config.progress`）。
> ⇒ **以运行期实测为准**，静态那处应属于相邻的另一条任务。

---

## 3. 结论二：★★ `mission_status` 决定追踪栏文案（**已验证**）

单变量实验（只改 `mission_status`）：

| `mission_status` | 追踪栏第一行 | 追踪栏第二行 | `mis_content` 长度 |
|---|---|---|---|
| **1** | 主线-斗罗魂师 | **去史莱克城找周漪** | **30** 字节 |
| **2** | 主线-斗罗魂师 | **去周漪老师处报告** | **27** 字节 |

- 「去周漪老师处报告」= 本地 `progress_edit_2 = '去{3周漪老师}处报告'` 的渲染结果
  （`{3…}` 占位被填掉；9 个汉字 × 3 = **27 字节** ✓）
- 两次都**无 nil、无乱码、无报错**

**⇒ `mission_status` 是"任务当前处于哪个阶段"的开关，直接切换文案模板。**

## 4. 结论三：`process_status` / `target` / `target_value` / `value` **不改文案**

单变量实验（`process_status` 0→1，并把 `target=20001, target_value=1, value=1`）：

```
t=misContent&v=mis_contentLen_30_mis_bid_10010_mis_code_0_mis_type_1   ← 仍是 30 字节，未变
追踪栏：第一行「主线-斗罗魂师」/ 第二行「去史莱克城找周漪」              ← 与基线相同
```

**⇒ 这四个字段不影响追踪栏文案**（它们的用途**待验证**）。

## 5. 结论四：**没有出现"完成/可提交"标记**

`mission_status=2` + `process_status=1` 时，视觉判读：

```
任务栏：主线-斗罗魂师 / 去周漪老师处报告
无"完成""可提交"字样，无对号/勾选标记
```

**⇒ "完成/可提交"标记**不由这两个字段直接驱动**，
需要另外确认（候选：`mission_status=3`、或需要与 NPC 10030 的交互、或需要 `12405` 的增量更新）。**

> 参考：Phase 4 时 `bid=10070`（`progress` 有 1 条）在 `status=2` 下曾显示过「**完成**」——
> 说明该标记与**任务自身的数据形态**有关，而 `10010` 的 `progress` 为空，走的是另一条分支。

## 6. 5G 的最终判定：`10010` 的"条件"是什么

综合 §2–§5：

| 层 | 结论 |
|---|---|
| **本地配置层** | **没有进度条件**（`progress` 为空）⇒ 客户端**不会**自己判断"打了几只怪/采了几个物" |
| **服务端层** | **`mission_status` 就是"阶段"**（1 = 去史莱克城找周漪；2 = 去周漪老师处报告） |
| **NPC 关联** | `commit_npc_id = 10030`（周漪）⇒ 提交对象是 NPC 10030 |
| **判定方** | **由服务端决定**何时把 `mission_status` 推到"可提交" |

**⇒ `10010` 的完成条件是"到周漪处提交"，而"到没到"由**服务端**说了算
（客户端没有本地条件可判）。**

**⇒ 这对 5H 的意义**：服务端在合适的时机（例如收到 `12403`、或判定玩家已到 NPC）
把状态推进即可，**不需要**实现任何"计数/条件引擎"。
