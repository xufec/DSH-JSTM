## 一、★ 修复的真实 bug（4 个）

### Bug 1（★ 最严重）：`14100` 有两个 handler，**旧版遮蔽新版**

**证据**：
```
行 4790: if cmd == 14100:            ← 旧版：读 config 的 signin_days / signin_is_get
行 5930: if cmd in (14100, 14101):   ← 新版（我的完整实现）
```
**⇒ 行 4790 先 `return` ⇒ 我的实现在 5938 **永不可达**。**

**加重问题**：旧版读的 `signin_days` / `signin_is_get` 在 `config.json` 里**根本不存在**
（真实键是 `sign_days` / `sign_is_get`）⇒ `is_get` **恒为 0**。

**修复**：删除行 4790-4803 的旧分支，统一交给后面的完整实现。

---

### Bug 2（★ 我自己的实现缺陷）：`14100` 的 `is_get` **读配置而非查 DB**

**证据**：
```python
# 修复前
w_u8(int(self.cfg.get('sign_is_get', 0)) & 0xff)   # ← 读配置，恒 0！
```
**⇒ 即使签到成功，客户端仍收到 `is_get=0` ⇒ 界面继续显示"可领取"。**
**★ 这正是用户报的"签到奖励还是不能领取"的另一半原因。**

**修复**：
```python
_got = 1 if db_sign_got(rid, days) else 0    # ★ 改为查 sign_got 表
w_u8(_got & 0xff)
```

**验证**：`14100 → is_get=1`（修复前**恒 0**）✓

## 五、★ 一处**虚警**（如实记录）

**执行过程中 `Get-Content | Measure-Object -Line` 报"5917 行"，看似比 6355 少了 438 行。**
**经复核**：`Measure-Object -Line` **只统计非空行**，实际总行 **6354**（非空 5917）。
**⇒ 没有代码丢失**，与备份逐项对比一致（112 分支不变）。
**教训**：PowerShell 的 `Measure-Object -Line` 不能用于统计"总行数"。
