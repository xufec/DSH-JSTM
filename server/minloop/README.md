# 绝世唐门 1.4.9 · 最小回环服务器（minloop）

> **一句话**：这是"**登录 → 角色 → 进场景 → 接任务 → 打怪 → 结算 → 掉落进包 → 提交 → 奖励 → 背包**"
> 这条最小玩法回环的**独立最小实现**（3 个文件），用来回答两个问题：
> ① 这条回环**最少**需要哪些命令、哪些字段；② 每个字段的值**能不能**取到原版真值。
>
> 它**不是** `server/mock_server.py`（16k 行全量服）的替代品 —— 那是"能玩"的服；
> 这是"**最小可验证**的服"，是**度量尺**与**回归基座**。

---

## 一、文件

| 文件 | 作用 | 行数 |
|---|---|---|
| `min_loop_server.py` | 服务器本体：协议规格编码器 + SQLite + TCP 游戏服 + HTTP 网关 | ~800 |
| `selftest.py` | **离线回环自检**：用真实协议规格驱动整条回环，逐帧严格校验 | ~300 |
| `replay_real_frames.py` | **真机帧回放**：把 MuMu 里 APK 真实发出的字节回放给本服 | ~160 |

```bash
python server/minloop/min_loop_server.py                    # 默认 8099/9099（避开参考服 8080/9000）
python server/minloop/min_loop_server.py --http 8080 --game 9000
python server/minloop/selftest.py                            # 离线自检（不需要模拟器）
python server/minloop/replay_real_frames.py                  # 真机帧回归
```

### 5.2 ⚠ 击杀奖励的证据等级（**自我更正**，goal 50 轮 · round 8）

击杀奖励里的 `coin` 取自 `analysis/1.4.9/item/_config_drop.json`（怪物 `20001` → `coin="{1000}"`）。
**但它不能被称作"已验证的真实发放值"**：

| 依据 | 原文要点 |
|---|---|
| `analysis/1.4.9/item/drop_model.md:291` | 「`Config.Drop` / `Config.DropItem` 是**服务端下发逻辑的客户端副本，客户端从不读取**」 |
| `analysis/1.4.9/item/drop_model.md:400`（§9.3） | 「**这批数据不能当作"绝世唐门 1.4.9 的掉落表"使用**」（29 个 `item_bid` 全在 `51000`–`51066`，属别家 IP 物品号池） |

⇒ 本服对它的标注为 **`[APK_CONFIG / 未实机验证]`**：
它是**目前唯一可得的口径**（优于我先前的 `[TEST_ONLY]` 编造值），
但**不保证与服务端实际发放一致**——因为客户端根本不读这张表，我们也无法用客户端行为反证它。
**判断可否升级为"已验证"的唯一途径**：拿到真机在击杀瞬间的 `10302`（货币同步）实际增量。

### 5.4 ★「**确有真实数据、但按纪律故意不填**」清单（goal 50 轮 · round 25-26）

有些命令我们**已经握有真实数据**，却因**关键字段语义未确证**而**故意回空**（填错会把客户端推进未验证状态）。
这些条目**不是"没做"**，而是**有意识的克制**；每条都写明升级所需的前置证据。

| 命令 | 已握有的真实数据 | 为何不填 | 升级需要 |

| `10922`（活动列表） | `server/_richang.json['tasks']` = **43 条**真活动（`id/name/max_num/desc_*`），`SC_10922.act_list[].id` 完全能对上 | `act_list[].status`（uint8）语义 **UNKNOWN**（0 是"未开放"还是"进行中"无据）；且**空表已被证实可接受** —— `analysis/1.4.9/protocol_flow.md:108`（参考服回"空但合法"）、`blank_dialog.md:227`（回 0 条时客户端显示"该功能暂未开放"） | 确证 `status` 语义（反汇编 `game/daily/daily_ctrl.luac` 或界面读数）；`int_args` 含义亦待确证 |
